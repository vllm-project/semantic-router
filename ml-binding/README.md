# Traditional ML native binding

`ml-binding` loads model-selection artifacts and runs KNN, K-Means, or SVM
inference behind a Rust/CGo boundary. Training happens in
[`src/training/model_selection/ml_model_selection`](../src/training/model_selection/ml_model_selection/README.md);
this module only serves trained JSON artifacts.

| Selector | Runtime behavior |
| --- | --- |
| KNN | Chooses a model from nearby training samples. |
| K-Means | Maps the query to the nearest learned cluster. |
| SVM | Applies the serialized multi-class decision function. |

## Build and test

You need Go 1.24.1 or newer, Rust, Cargo, CGo, and a C compiler. Native Windows
is not supported; use Linux, macOS, or WSL.

```bash
cd ml-binding
cargo build --release
cargo test

export LD_LIBRARY_PATH="$PWD/target/release${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
go test ./...
```

On macOS, set `DYLD_LIBRARY_PATH` instead. From the repository root,
`make test-binding-minimal` runs the maintained cross-binding check.

## Use from Go

Load the artifact that matches the selector, call `Select`, and close the
selector when it is no longer needed:

```go
data, err := os.ReadFile("models/knn_model.json")
if err != nil {
    return err
}

selector, err := ml.KNNFromJSON(string(data))
if err != nil {
    return err
}
defer selector.Close()

model, err := selector.Select(features)
```

`KMeansFromJSON` and `SVMFromJSON` follow the same lifecycle. The feature vector
must have the same shape and ordering used during training; the binding does not
repair an incompatible artifact.

See [`ml_binding.go`](ml_binding.go) for the complete public Go API and
[`Cargo.toml`](Cargo.toml) for pinned Rust dependencies.

## Artifact compatibility and prediction rules

New Python exports use `format_version: 2`. Upgrade the native runtime together
with the training tools before serving these artifacts; older runtimes do not
understand the version 2 SVM parameters.

- SVM stores the exact fitted SVC support vectors, signed dual coefficients,
  intercepts, and per-class support counts in `svc`. Linear and RBF inference
  use the training feature scale (`input_normalization: "none"`) and libsvm
  one-vs-one voting, including binary sign conventions and first-class vote
  ties. Runtime inference does not normalize the input again.
- Existing unversioned Python SVM exports contain those exact parameters at
  the top level. The loader uses them in preference to the old approximate
  per-model classifiers, so these files do not need retraining. Unversioned
  native-only `linear_classifiers` / `rbf_classifiers` artifacts retain their
  original normalized-input, one-vs-rest behavior. They cannot recover a
  missing fitted SVC; re-export the trained model to adopt version 2.
- KNN uses Euclidean distance on L2-normalized feature vectors (cosine ordering
  for nonzero vectors). A zero vector remains zero. Neighbors sort by distance
  and then artifact sample index; equal model totals select the
  lexicographically first model name. Voting is
  `0.9 * quality + 0.1 / (1 + latency_ns / 10_000_000_000)`.
  Unversioned KNN files use these corrected rules too. Revalidate held-out
  routing results when upgrading: old Rust used raw Euclidean distance and
  dataset-relative latency scaling, which disagreed with Python training.

The KNN/SVM loaders reject malformed feature shapes, nonfinite values, and
inconsistent sample or support counts. Their request feature-dimension
mismatches return an inference error through the Go/C ABI instead of reaching
a matrix-operation panic.

`cargo test` includes checked-in fixtures generated by sklearn. For a fresh
training/export/C ABI comparison (including binary and multiclass SVM, both
kernels, KNN ties, old Python artifacts, and Python reload), run from the
repository root:

```bash
python -m pip install numpy scikit-learn pytest
python -m pytest src/training/model_selection/ml_model_selection/tests/test_native_parity.py -q
```

The test builds the current checkout's native library with Cargo. It does not
require Torch, model downloads, or a GPU.
