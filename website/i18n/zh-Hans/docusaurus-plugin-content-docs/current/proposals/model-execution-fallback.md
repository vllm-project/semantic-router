# 模型执行回退

## 状态

未来执行编排层的设计边界。

## 问题

端点重试和异常端点剔除可以恢复到同一逻辑模型的另一个副本。它们无法安全地切换到另一个逻辑模型，因为请求正文、提供商转换、凭据、成本策略和会话连续性都可能发生变化。

## 归属边界

- 信号层和决策层选择预期的逻辑路由。
- 选择层和 Router Learning 选择初始模型。
- Envoy 在该模型的后端集群内重试传输失败。
- 未来的执行编排器负责在上游尝试失败后进行跨模型回退。

跨模型回退不得通过再次运行 DecisionEngine 来实现。

## 提议的契约

每次尝试都记录：

- 所选的逻辑模型和物理端点
- 可安全重试的失败类别
- 请求流式传输状态
- 提供商请求标识符
- 成本预留和已观测用量
- 会话/对话标识
- 最大尝试次数和已访问模型

仅当响应字节尚未提交时才允许回退。上下文窗口失败和策略失败可以选择显式声明的兼容回退。默认情况下，身份验证错误、无效请求和流式传输中途失败不会重试。

## 必需的安全门控

- 在各次尝试之间传递幂等键
- 限制尝试次数和总超时时间
- 一条回退链中不得重复使用模型
- 对工具、响应格式、模态和上下文窗口进行兼容性检查
- 为每次尝试和最终结果生成 Router Replay 记录
- 将结果证据返回给 Router Learning

## 交付顺序

1. 交付端点级重试、熔断器和被动异常端点剔除。
2. 添加类型化失败分类和仅用于重放的诊断信息。
3. 为连接/重置失败实现非流式回退。
4. 添加显式的上下文窗口和策略回退映射。
5. 仅在定义 API 契约后评估流式回退。
