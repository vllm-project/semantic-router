# Dual-Head Classifier Experiment

This experiment shares one DistilBERT encoder between two tasks:

- sequence-level category classification;
- token-level binary PII detection.

It is a small synthetic-data prototype for studying multi-task training. It is
not a supported router model, a production PII detector, or a published quality
baseline.

## What Is Included

| File | Purpose |
|---|---|
| `dual_classifier.py` | shared encoder and the two prediction heads |
| `trainer.py` | dataset alignment, weighted loss, training, evaluation, and save logic |
| `data_generator.py` | template-based categories and synthetic PII patterns |
| `train_example.py` | short end-to-end training demonstration |
| `example.py` | inference API demonstration using an untrained model |
| `test_dual_classifier.py` | model, prediction, and save/load tests |
| `test_dual_classifier_system.py` | data, loss, trainer, and integration tests |

The generator uses ten template categories and five PII pattern families. Its
samples are useful for exercising code paths, not estimating real-world
accuracy or privacy coverage.

## Run the Experiment

Create an isolated environment with PyTorch, Transformers, NumPy,
scikit-learn, tqdm, psutil, and pytest, then run from this directory:

```bash
python train_example.py
```

The example downloads `distilbert-base-uncased`, trains on a deliberately small
synthetic dataset, and writes a checkpoint under `trained_model/`.

To load that checkpoint:

```python
from dual_classifier import DualClassifier

model = DualClassifier.from_pretrained("trained_model", num_categories=10)
category_probabilities, pii_probabilities = model.predict(
    "Contact me at name@example.com"
)
```

`category_probabilities` has one row per input. `pii_probabilities` has one
binary distribution per token. The caller is responsible for keeping tokenizer
tokens aligned with the returned token predictions.

## Validate

```bash
python -m pytest test_dual_classifier.py test_dual_classifier_system.py
```

The tests download the DistilBERT model and tokenizer unless they are already
cached. Passing tests verify code behavior only; they do not validate the
synthetic label policy or production fitness.

## Extending the Prototype

Before using the architecture with real data, define an explicit category
mapping, a token-label alignment policy, representative train/validation/test
splits, and metrics for each PII entity type. Evaluate privacy recall and false
positives on data that was not generated by these templates.
