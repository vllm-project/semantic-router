## 1. What changed

Only the package runtime's `decision2/qwen.py` (IX1 commits `8e6bdfc33`, `e876fbefc`; integration `fea2f016b`). On a
GPU, a request whose padded question batch would put more than 2^30 elements in a gated-delta q / k / v tensor runs as
several batches, longest questions first, because the FLA kernels use 32-bit offsets. Budgets in padded tokens:
0.8B / 2B 524,287; 9B 262,143; 27B 174,762. Requests that fit keep the old path. Each package differs from the
replaced auto_map revision in exactly three files: `decision2/qwen.py`, `MODEL_MANIFEST.json` (digests; builder commit)
and `README.md`. The card gains one line: "**Runtime update:** very long multi-question requests are processed in
GPU-sized batches (previously they could fail on extremely long inputs); answers unchanged." Weights, tokenizers,
calibration, the vendored training/model sources and the Transformers remote code are byte-identical.
`runtime_source` and `automap_source` are pinned to integration `99432d1a7`, which contains the fix and the auto_map
remote code. DEV2.0-4B carries the fix already (`13d42143`). DEV2.0-0.6B has no gated-delta layers, so it is skipped.

## 2. Procedure (node E GPU6–7, one render node per container)

`ops/make_budget.py` derives each spec and final decision from the auto_map final. The decision carries the judgement
forward and supersedes `<repo>@<auto_map revision>`. `ops/budget.sh <tier>` then runs three steps:

1. `--stage`: `release.sh` without parity or upload. It builds the package, runs the native examples and card, and
   checks AutoConfig / AutoTokenizer / AutoModel / pipeline against native and the card's Transformers block.
2. `--extra`, on the staged package:
   - `gpu_long_request`: one prompt at the cap minus 300 tokens. 32 questions on 9B and 27B, 48 on 0.8B and 2B, so
     the batch exceeds the budget on every tier. Each answer is compared with the question asked alone.
   - `runtime_bench`: old against new.
   - For 27B, `gpu_private_requests` on IX1's two recorded requests. They were relayed node D → node E into a private
     directory, and the receipt holds counts only.
3. `--release`: refuses unless `main` is still the superseded revision, `--extra` passed, and a fresh build equals the
   tested package byte for byte (manifest SHA-256). Then it runs `hf_headroom.sh` and `release.sh --upload --collect
   --already-collected`:
   - full parity on typed-final 1,600, css15 6,547, public231 231 and mlx-diag 2,275, before and after the real
     download;
   - AutoModel parity compared answer by answer with native;
   - the card's Transformers block from the Hub in a fresh `HF_HOME` under Transformers 5.17.0 and 5.18.0;
   - readback, gate seal and collection readback.

   Card HTTP, links and `gate evaluate` follow. No history rewrite and nothing deleted. One publisher at a time per
   repository.

## 3. Long-input regression and the 27B recorded requests

- **0.8B / 2B** (48 questions, long prompt 16,084 tokens): two forwards, 32 × 16,088 and 16 × 392. 48 / 48 valid and
  equal to alone (drift 0.006 / 0.004).
- **9B** (32 questions): two forwards, 16 × 16,088 and 16 × 392. 32 / 32 valid and equal to alone (drift 0.009).
- **27B** (32 questions, long prompt 32,468 tokens): two forwards, 5 × 32,512 and 27 × 496. All 32 valid and within
  budget.
  - The first run (`27b/extra-strict/`) failed the test as written on one question. q24 is a generated Noul question
    with P(true) 0.4997 alone and 0.5029 in the split: a side flip at drift 0.003.
  - `gpu_long_request_diag` (`27b/diag/`) asked it within the request's 31 short questions. That is one batch on the
    single-batch path the budget leaves unchanged, and it gives 0.4905 with both the old and the new package
    (bit-identical): the same batch-shape noise on a coin-flip question.
  - The regression gained `--tie-margin`. With it, a side flip within the tolerance of a question whose alone answer
    lies within 0.02 of its boundary is listed as a tie, not a mismatch; the default is unchanged. The 27B run used
    `--tie-margin 0.02`: 31 / 32 equal to alone, q24 listed as a tie (0.0003 from the boundary), pass. The 27B
    decision says so.
- **27B recorded requests** (IX1's private repro: 32 questions each; padded single batch 455,168 and 725,760 tokens,
  which on the released runtime gave one `invalid_model_output` and one GPU memory fault). Each ran whole twice:
  - forwards 12 × 14,224 + 20 × 272 and 7 × 22,680 + 25 × 464;
  - **32 / 32 valid, 32 / 32 equal to each question asked alone** (max drift 0.0034 and 0.0022);
  - the second run unchanged; wall 23–35 s; peak 95.2 and 93.4 GiB.
