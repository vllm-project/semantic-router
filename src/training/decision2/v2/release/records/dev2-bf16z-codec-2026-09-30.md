## Result

- **Codec `bf16z/1`** (`v2/release/runtime/bf16z.py`, ZipNN idea, `zstandard` only):
  - Each tensor's bytes are split into byte planes: the BF16 sign / exponent byte and mantissa byte; all four bytes of
    an FP32 tensor.
  - Each plane is stored with zstd (level 19), or raw when zstd does not shrink it.
  - The original safetensors header is kept verbatim, so parameter counts need no decompression.
  - Decompression rebuilds the exact file and checks its SHA-256.
- **Pipeline:** the builder, layout, package runtime and successor gate support it in separate commits. Plain packages
  are unchanged, and all 120 release tests pass, plus 8 bf16z tests with numpy + zstandard.
- **F-b** (27B M4b full fine-tune, exact-parity BF16 package), measured on node B:
  - **53.80 → 34.65 GB (64.4%).** The FP32 embedding went 5.09 → 2.06 GB (40.5%) and the BF16 shards 48.71 → 32.59 GB
    (66.9%).
  - That fits: 50.46 + 34.67 GB = 85.1 GB, leaving 14.9 GB of headroom.
  - All 27 compressed shards restore bit for bit, matching the BF16 copy's SHA-256 (33 s).
- **Stopped by the coordinator's 07:20 decision:** A20r is the 27B successor. The F-b package was built and moved to
  node A, but item 8 was not run and nothing was uploaded.
  - The C1 ledger is untouched by this worker. A20r's own C1 collection was running on node A when this stopped.
- **End-to-end check on DEV2.0-0.8B** (BF16 revision `bede7938`, no upload):
  - bf16z 2.014 → 1.198 GB (59.5%).
  - `release.sh` build → examples in two processes → card example → parity passed through the runtime's restore:
    0 answer changes on typed 150, CSS15 200, public 231 100 and mlx-diag 150 prompts, drift ≤ 4.4e-16.
  - The restored identity `3f02f0e5` equals the released one.
- **Direct node-to-node link:** node B → node A over ssh (tar, AES-GCM) moved 53.84 GB in 43.4 s, **1.24 GB/s**.
  - Every file of the transferred package re-hashed equal on node A (59 + manifest).
  - The temporary key is removed from both nodes.
- **GPU: 0.103 GPU-h.** Two CAL698 refits on node B GPU0 (0.037 + 0.036) and the 0.8B end-to-end run on node A GPU1
  (0.030). Compression, verification, builds and the transfer were CPU only.
