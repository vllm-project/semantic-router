**Prediction vs outcome:** mxcx COLLAPSE — not flagged; cx COLLAPSE or WARN — not flagged; mxcxa and T soup neither —
mxcxa unflagged, T soup WARN. **The check does not detect the collapse.**

Reading (not a preregistered test): the typed FINAL collapse of mxcx (to level 4) does not appear on in-family A7q rows.
All m6 soups (Lux targets on these rows) reproduce a similar in-family level distribution, over-using level 0 and
rarely using level 1 (2–4%, near the 2% rare line), and beat the T soup here; the collapse is an out-of-family behaviour.
A FAMILIAR in-family 5-level panel is therefore the wrong instrument for it. By the same reasoning, a per-level bias
correction fitted only on in-family A7q slices may not transfer to typed FINAL (for the 0.6B track and coordinator to weigh).

Context only (no flags): the T soup's existing HT-DEV collection gives gold-free level usage on HT-DEV's 5-level
`empathy/empathic_reactions` task of 18 / 5 / 19 / 185 / 23 (modal share 0.74, 250 items). No HT-DEV collections exist
for the m6 soups, so this context cannot separate mxcx from mxcxa; none were run (outside the prereg).

GPU time: 27.9 s (mxcx), 28.4 s (mxcxa), 30.4 s (cx), 29.7 s (T soup) = 116.4 s ≈ 0.032 GPU-h (runner `GPU-TIME.json`).

## Run command for new candidates (node A)

```bash
SRC=<full-sha>-src_training_decision2; S=/data/dev2/src/$SRC/src/training/decision2; export PYTHONPATH=$S   # code >= 1eb2d2928
$S/v2/eval/run_same_panel.sh --gpu <N> --track <track> --src $SRC --run-dir <run> --model-dir <pkg> [--shared-lease <name>] \
  [--env TRITON_CACHE_AUTOTUNING=1 --env TRITON_CACHE_DIR=<rw dir> --mount-rw <rw dir>] \
  -- --adapter-spec <adapter.json> --model-path <pkg> --revision <id> --panels score5-dev   # or typed-dev,css-pilot,score5-dev
python3 -m v2.eval.htdev.score seal --prompts /data/dev2/private/panels/goldfree/score5-dev.prompts.jsonl \
  --predictions <run>/output/score5-dev.predictions.jsonl --output <run>/SEAL-SCORE5.json
python3 -m v2.eval.dev_readout --run-dir <run> --label <ckpt> --output <readout.json>
```

The readout JSON gets a `score5` block (`histogram`, `modal_level`, `modal_share`, `rare_levels`, `invalid_or_missing`,
`correct`, `accuracy`, `accuracy_ci95`, `macro_f1`, `qwk_answered`, `always_modal_accuracy`, `by_axis`, `flags`); stdout adds
`score5.accuracy`, `score5.modal_share`, `score5.rare_levels`, `score5.flags`. With `output/ht-dev.predictions.jsonl` it also
gets `htdev_empathy_levels` (context). Existing blocks are unchanged. Given the validation result, read the block as an
in-family level-usage readout, not as a collapse detector.
