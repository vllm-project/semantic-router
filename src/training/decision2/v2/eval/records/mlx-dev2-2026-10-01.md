# MLX-DEV2: a held-out multilingual development guard that tracks formal mlx-diag

Eval & peers track, successor-rule item 4. **Development panel, never a release score.**
Builder, isolation scan, scorer and paired comparison: `python3 -m v2.eval.mlx_dev2
{pool,scan,build,predictions,score,compare}`; readout runner `v2/eval/mlx_dev2_run.sh`;
registered as `mlx-dev2` in `v2/eval/panels.py`.

## Why

Four breadth candidates passed every development gate and then failed only on formal
mlx-diag (card-eligible Choice + Noul): 4B `4b-LHA10SD` −.029, 0.8B `08b-RA` −.014,
27B M5-L128 −.013, Gemma MoE −.036. The old MLX-DEV (decoder track; answerability Noul,
MIRACL, MTOP, JCommonsenseQA, Score A7) read the first two as +.009 and +.006: it measures
different tasks, so it cannot track mlx-diag.

## Panel

Same construction as mlx-diag's card part (`v2/eval/multilingual_panel.py`): the same
languages, task families, English instructions and options, target-language states and
byte-identical question objects. Items come from the publishers' non-test splits only.
There is no Score part; mlx-diag's Score uses XNLI (CC BY-NC).

| Type | Source (non-test split) | Licence | Languages | Source items × languages |
| --- | --- | --- | --- | --- |
| Choice | MASSIVE 1.1 **dev** partition, archive `4cba5faa…` | CC BY 4.0 | en ar de es fr ja zh | 345 × 7 = 2,415 |
| Noul | PAWS-X `4cd8187c` **validation** split | free use with attribution | en de es fr ja ko zh | 400 × 7 = 2,800 (200 / 200 labels) |

- **Size and hashes.** 5,215 prompts, SHA-256
  `35747a2679c86cac6577ed2e254f6fe9fafb673ef1af6fb5ff29589d2f9d8b73`; gold
  `9d9398f4a5753cebf750429c6089ef833e7bf1f9d8f67bb5c330f9cdc01ee426`.
- **Selection.** Rows are chosen by a salted hash of the source ID (salt `mlx-dev2-v1`), never by
  model output.
- **Choice eligibility.** The same localisation filter as mlx-diag must pass in all six non-English
  locales.
- **Choice quota.** At most 25 IDs per scenario. Scenarios with few clean dev rows are under-filled:
  - audio 0;
  - transport 3;
  - music 5;
  - social and takeaway 10 each;
  - alarm 17;
  - the other 12 scenarios 25 each.

  All 18 options stay in every question.
- **Disjointness by split.** mlx-diag uses the TEST splits, so no source row is shared. No
  MLX-DEV2 state equals any mlx-diag state (checked).
- **Isolation scan** (`mlx_dev2 scan`). This extends the mlx-diag audit's rule: exact
  normalised match, plus a shingle share of at least 0.5. Shingles are word 8-grams, or 16-character
  shingles for short text. Two additions:
  - a pool text of 4–7 words that is contained in any corpus string is flagged;
  - exact matching also covers corpus strings under 12 characters.

  The corpus is every file named like train / replay / aho / mixture / prompts / targets /
  dev-private / select / cal / panel under the program data roots of nodes A and B. That
  includes every panel's prompts, mlx-diag, the bench directories, the MASSIVE-derived
  multilingual data and the `f8c50b13` training snapshot. Prediction, result and log
  directories are excluded.
  - Coverage: 2,945 unique files on A (9.9 M rows, 18.4 GB) and 2,574 on B (7.7 M rows,
    11.3 GB), deduplicated by content. 0 unreadable.
  - Flagged and excluded in every language: 487 of 1,327 eligible MASSIVE dev IDs and 267 of
    1,928 PAWS-X validation pairs. Mostly short commands and Wikipedia sentences in
    MASSIVE-derived development data and paraphrase mixes. B's flags are a subset of A's.
  - Known limit: containment within CJK text without spaces is not detected. Because a flag
    in any language drops the ID in all languages, the en / de / es / fr parallels cover
    it.

## Validation (before adoption)

Frozen packages, formal runtime (`examples.py parity`, frozen image), one leased GPU each.
Every package read both panels in the same container. Comparison: paired, stratified by
type × language, 5,000 replicates, seed 20260927 (`v2.dec.mlx_paired.statistic`). Each delta
is the card-eligible score (mean of the Choice and Noul macros), candidate − reference, with its
95% CI. The mlx-diag column is this run's reading. It reproduces the formal values (−.0287,
−.0136, +.0377, −.0037, −.0129) to four decimals.

| Pair | Required | mlx-diag (formal) | MLX-DEV2 | CI half-width | Verdict |
| --- | --- | ---: | ---: | ---: | --- |
| 4B `4b-LHA10SD` vs LH | flag | −.0287 [−.0394, −.0184] | **−.0284 [−.0345, −.0226]** | .0059 | FLAG ✓ |
| 0.8B `08b-RA` vs DEV2.0-0.8B | flag | −.0136 [−.0256, −.0024] | **−.0192 [−.0265, −.0123]** | .0071 | FLAG ✓ |
| 27B M5-L128 vs A20r | flag | −.0129 [−.0244, −.0019] | **−.0088 [−.0141, −.0037]** | .0052 | FLAG ✓ |
| 4B LH vs DEV2.0-4B (`fadbba4f`) | pass | +.0377 [+.0256, +.0498] | **+.0147 [+.0077, +.0220]** | .0071 | PASS ✓ |
| 9B K-a13IB vs DEV2.0-9B | pass | −.0037 [−.0110, +.0034] | **−.0018 [−.0062, +.0026]** | .0044 | PASS ✓ |

- **All five verdicts are correct.** The rank correlation with the formal deltas is
  **Spearman 1.00** (identical order); Pearson 0.94.
- **Precision.** CI half-widths are .004–.007, against the target of at most .010; mlx-diag's
  are .007–.012. A −.015 card delta is detectable.
- **Per type.**
  - Noul tracks closely where mlx-diag's Noul moves (MLX-DEV2 vs mlx-diag):
    - LHA10SD −.054 vs −.053;
    - LH +.041 vs +.041;
    - M5-L128 −.024 vs −.026.
  - For 08b-RA, MLX-DEV2 splits the loss across both types (Choice −.020, Noul −.019), where
    mlx-diag puts it all in Choice (−.027, Noul .000).
  - Choice is the weaker half. LH vs DEV2.0-4B reads −.012 on MLX-DEV2 against +.034 on
    mlx-diag. A plausible cause is the dev-split scenario mix (audio is empty and transport and
    music are thin). Per-type values are reported, but only the card value gates.

## Adopted rule (development guard)

**MLX-DEV2 guard: PASS iff the card-eligible (Choice + Noul) paired delta of the candidate vs
its reference has a 95% CI upper bound ≥ 0** (stratified paired bootstrap, 5,000 replicates,
seed 20260927; `guard_pass` in `mlx_dev2 compare`). The reference is the model the candidate
would replace (incumbent or parent).

- **Scope.** The rule is required for every breadth arm before any formal panel is read, and it
  replaces the old MLX-DEV for this purpose.
- **Limits.**
  - A PASS does not replace formal mlx-diag at release; the successor rule 4 check still
    decides.
  - The guard is a screen against regressions, not an estimate of the formal delta. Positive
    deltas read smaller here.

Run (node side; outputs stay private):

```bash
v2/eval/mlx_dev2_run.sh --gpu G --package PKG --work /data/dev2/private/.../run \
  --panel PANEL_DIR [--diag MLX_DIAG_DIR] [--cache TRITON_CACHE | --frozen-27b DIR --expect DIGEST]
python3 -m v2.eval.mlx_dev2 compare --panel /data/dev2/private/panels/mlx-dev2-v1 \
  --candidate CAND/mlx-dev2.predictions.jsonl --reference REF/mlx-dev2.predictions.jsonl --output OUT.json
```

`PANEL_DIR` holds `prompts.jsonl`. The runner answers through `v2/eval/ix1/probe.sh` (lease
check, render-node isolation, `--network none`). A 0.8B–9B package takes 3–5 GPU-minutes; 27B
takes about 17.

## Cost and artifacts

- **GPU: 1.07 GPU-h**, 9 readouts of 7,490 prompts each:
  - node C GPUs 1–5: 0.80 GPU-h;
  - node D GPUs 4–7: 0.27 GPU-h.

  Leases were checked and released. Node C GPU0 was not touched.
- **CPU:** pool, scans (about 5 minutes per node) and the build.
- **Panel** on nodes A and B: `/data/dev2/private/panels/mlx-dev2-v1/` (prompts, gold,
  manifest, both scan reports), plus `goldfree/mlx-dev2.prompts.jsonl` and
  `gold/mlx-dev2.gold.jsonl`.
- **Validation predictions and comparisons:** node A `/data/dev2/private/eval/mlx-dev2/{runs,compare}/`.
