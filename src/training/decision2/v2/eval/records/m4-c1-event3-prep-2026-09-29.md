## 5. The event script

`event3.sh --gpu N --src MIRROR [--peers27 K,K] [--c27 f1|f2] [--models K,...] [--c27-package …]
[--shared] [--lease-name owner.NAME] [--verify-only | --preflight-only]`:

- **Model table:** `event3-models.json` is the one block to edit (rows, the F1/F2 blocks, the card-eligible
  27B list). Arguments override the selection, the 27B candidate and its package.
- **Plan:** `event3.py plan` resolves the table and refuses anything outside the rules (section 3).
- **Verify (CPU):** checks the images by ID, adapter modules in the mirror, paths, release manifests
  (every file, the weights identity and the base files), pinned tree digests and frozen-cache digests.
- **Smoke:** each collected model runs the first 80 prompts of typed FINAL and public 231, which cover
  all three types. Models with a frozen cache take a fresh copy. The parity check against the stored
  formal run is `exact` (answers identical, probability drift ≤ 1e-4) for the candidates, Sol 16K,
  Kai 8K and the 27B rows, and `near` (at most 10% of answers differ) for the runs imported from an
  earlier session.

**Fixes over event 2's script:**

- **Smoke outputs:** smokes write to their own directory `c1-event3-preflight/<mode>-<UTC>/`.
- **When the event counts as used:** `c1-event3/` is created, and the event is used, only when
  decryption starts. A failed smoke leaves C1 untouched and the event re-runnable.
- **Key handling:**
  - The key is read once, after every smoke has passed and the stored event-2 seals have been re-checked.
  - Until then no child process can read stdin: stdin is `/dev/null` and the key waits on fd 3, which
    every child has closed.
  - `--preflight-only` closes stdin and never reads the key.
- **Logging:** `ACCESS.log` is written only in event mode. Every step also goes to `EVENT.log` and
  `PREFLIGHT.log`.
- **Integrity checks:** the encrypted bundle's hash (`d924389a`), the prompts' hash and the gold's hash
  are checked.
- **Relaunch:** a collection that fails before writing any prediction is relaunched once and logged,
  as for Kev in event 1.
- **Scoring:** paired comparisons run in parallel. `EVENT3-SUMMARY.json` collects C1, the paired
  deltas and GPU-hours.
- **Lease:** each runner job writes the named entry `gpuN.lock/owner.eval`, and the entry is restored
  on exit. `--shared` is needed only if a co-tenant holds the GPU.

the event survives a dropped SSH session; the key is already in the pipe.

## 7. Smoke-before-decrypt procedure

1. Plan and rule check. Then verify every image, module, package, tree and cache hash (CPU).
2. For each collected model: take a fresh copy of its frozen cache if it has one, run the
   80 + 80-prompt smoke, and record the cache's post-run state. Then run parity against the stored
   formal run and, for candidates, check that every row carries the release weights identity.
3. Re-check the seals of the stored event-2 predictions, by hash only.
4. Only then read the key, create `c1-event3/` ("event 3 used"), check the bundle hash and decrypt the
   prompts.

A failure in steps 1–3 exits before the key is read. It is logged in `ACCESS.log` (event mode) and in
`PREFLIGHT.log`, and the event is not used.
