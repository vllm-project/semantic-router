## 3. Engine adapter (released `dev2-package/1` packages)

`publication.decision_index_release_engine:ReleasedDecisionIndexEngine`, a kit `Engine` over the package's own
`Decision2.from_pretrained(pkg).system_one(state=, questions=)`, imported from the package directory only.

- Original state, question IDs, instructions, option keys, order and descriptions are passed unchanged; one request
  per call; the package encodes all questions of a request in one batch.
- Never truncates. A question over the package's `max_input_tokens` (`max_length_exceeded`) makes the whole request
  `Unsupported`. A shape the package's `question_to_row` rejects (`invalid_question`) is also `Unsupported`, with its
  reason recorded; its count is reported.
- Every option must receive a finite probability in [0, 1], summing to 1 within 1e-5, and the chosen key must be the
  unique argmax; anything else is an `error`.
- Package calibration as shipped (all six are `calibration: null`, T = 1). No prompt or option change per benchmark.

## 4. Gates before a full run (per package)

1. Suite verify on node C and node D: kit `suite verify` and the port's `verify-suite` (row and ID hashes above).
2. **86-request compatibility and native parity** on the run node, GPU class and image: (a) the kit runner with the
   adapter; (b) the package's `system_one` called directly outside the kit, in a separate process. Gate: 86 / 86
   `ok` or declared `unsupported`; identical chosen keys and unsupported decisions; max |Δp| ≤ 1e-4 (value
   reported). Both processes use copies of one frozen Triton autotune cache filled by the reference pass. On a
   mismatch: stop, fix the adapter, repeat once.

## 5. Full runs

- Order: 27B (node D, GPU0–7), then 4B and 9B (node C, GPU1–7; never GPU0) as cross-checks of the external report,
  then 2B, 0.8B, 0.6B.
- Rows are split into k shards by a fixed hash of `run_id`; one kit runner process per GPU, each with its own copy
  of the frozen autotune cache; seed = kit `RUN_SEED`; requests are not batched across rows. Resume only after an
  interruption (errors retried; `unsupported` final).
- Latency: median and p95 of the kit's per-request `model_request_wall_ms` (MI325X, single process per GPU; not
  comparable with the board's RTX PRO 6000 latency rule). GPU-hours = wall-clock × GPUs, including load and warm-up.

## 6. Scoring and comparison

- Dual scoring of the merged `results.jsonl`: the port `score` and kit `87d4650b` `score --edition 0.2.1`. Gate:
  every benchmark within 1.5e-4 and the headline within 0.01.
- Per-benchmark comparison with the external report; every |Δ| > 1 skill point is explained (row accounting,
  unsupported counts, numerics, per-row prediction agreement where data allow).

## 7. Contamination audit (CPU)

Row-level, against each model's actual training data revisions from its release record. Matching: NFKC, casefold
and `\w+` tokens; exact match of a whole string or sentence, and 13-gram hits, over `state`, instructions and option
text. Positive controls: public train splits known to be in the training data. Reported: overlapping run IDs per
benchmark (private) and an override-adjusted value with the declared forcing rule "an overlapping row counts as
wrong", next to the unadjusted value.

## 8. Calibration study (no Index rows in any fit)

- Fits: one temperature per type and a Noul temperature + bias (Platt), fitted by NLL only on our own held-out
  calibration / development data (named per size in the results, with hashes); never on Index rows.
- Rescoring: the stored Index predictions (kit scorer) and, from stored predictions, our own panels (JevArena v3
  typed / CSS15, HT-DEV v2, mlx-diag, public 231), to judge whether a calibration-only revision would pass successor
  items 1–8. Answers of Choice questions cannot change under a temperature; Noul decisions at 0.5 can under a bias.
- A recommendation per size; nothing is published or uploaded to model repos by this campaign.

## 9. Gap analysis and data-plan input (private)

Per size against the frontier peer at Space index `a5a4aa0a`: the task families that drive the deficit, classified
as knowledge loss (below the size's own base or 1.0 parent), missing task coverage (no training family), or a
threshold / readout effect (ranking intact, level shifted). Candidate licence-clean training sources for the deficit
families (train splits only) with licence and row-level overlap risk against the Index rows and our held-out panels;
NC and ShareAlike-incompatible sources are excluded.

## 10. Policy

No checkpoint selection or tuning on Index rows; no per-benchmark prompt adaptation; frozen packages only. Rows,
predictions and logs stay in the node private directories.
