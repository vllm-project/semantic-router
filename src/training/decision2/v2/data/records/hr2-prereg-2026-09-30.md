# Preregistration — HR2: new licence-clean human-rated training data (research & data, 2026-09-30)

Committed and pushed at 2026-09-30 ~12:45 UTC+8, **before any HR2 row is converted**, before any audit and before any
row is shown to a reviewer. Assignment: coordinator cross-track note 2026-09-30 11:30 (HR2). Binding rules also from
the notes of 09:50, 04:10 (HT-DEV v2), 02:25 / 00:25 (data-quality process), 2026-09-29 23:40 (C1), 17:15
(JevBench), 16:40 (typed-family and panel rules) and 16:20 (C1 independence), plus the licence and persistence
policies. Worktree / branch `xunzhuo/decision-2-training-data-hr2`.

**Why HR2.** Typed / A7 gains inflate v3 without carrying over to fresh human-labelled data (4B vs Nox level on C1;
27B A20r +5.15 v3 but +0.23 C1; A7, HS1 and teacher soft targets did not move human transfer). HR2 adds human
judgments from sources no arm, panel or Decision 1.0 lineage has used: preferences → Choice, yes/no labels → Noul,
ratings → Score.

Before this commit only source metadata, licences, file schemas and upstream class counts were read (source audit,
§1). No row was rendered, sampled or scanned.

## 2. Label derivation (fixed now)

Rows follow `training.model.data` (native Choice / Noul / Score, `input_sha256` over state, instructions, options,
task type). Instructions and option descriptions are English; content stays in its language. Noul options are
`false` "No" / `true` "Yes". Every hash below is SHA-256 of the quoted salt plus a stable upstream key; "hash order"
means ascending by that hash.

### 2.1 HelpSteer3

- Context rendered as `User:` / `Assistant:` turns ending with the last user turn. Rows whose rendered state exceeds
  **12,000 characters** are dropped (length cap for review and training cost; reported).
- **Lineage screen:** a sample is dropped if its normalized first user turn (NFKC, casefold, whitespace collapsed)
  equals, or its first 200 normalized characters equal those of, the first user turn of any HelpSteer2 TRAIN /
  validation / preference prompt.
- **Group:** normalized first user turn (every sample sharing it is one group, across both families).
- **`hs3_pref` (Choice):** keep a sample only if `overall_preference` ∈ {−3, −2, +2, +3} **and** every released
  individual score is non-zero with the same sign (≥ 2 individual scores). **Ties (0), slight preferences (±1) and any
  split annotator are excluded.** Gold = the preferred response. The two responses are shown in the state as
  "Response A" / "Response B"; which one is A is set by `hash("hr2-ab-v1:" + key) % 2`; options are fixed
  `a` "Response A", `b` "Response B". Quotas by domain in hash order: multilingual ≤ 3,500, code ≤ 2,500, STEM ≤ 1,500,
  general ≤ 1,500 (shortfalls filled from general, then STEM). **Length balance:** within each domain the share of rows
  whose gold response is the longer one is brought into [0.45, 0.55] by dropping surplus rows in hash order.
- **`hs3_help` (Score, 5 levels):** from `feedback/`: each released feedback text of a response must open with "The
  response is {not | slightly | partially | mostly | perfectly} helpful" (levels 0–4). Keep a response only if all
  three released feedbacks parse **and max − min ≤ 1** (low agreement excluded). Gold = median. One response per
  sample (`hash("hr2-help-v1:" + key) % 2`). Level cap: no level above 30% of the family (surplus dropped in hash
  order). Target 5,000.

### 2.2 ETHICS (TRAIN files only)

- **`eth_util` (Choice):** each row pairs a scenario annotators ranked more pleasant with a less pleasant one. Gold =
  the more pleasant scenario, shown as A or B by `hash("hr2-ab-v1:" + key) % 2`; same length balance rule as
  `hs3_pref`. Group = first 8 normalized words of the more pleasant scenario. Target 3,500.
- **`eth_cs` (Noul):** `is_short = True` rows only (MTurk-written; the Reddit-derived long split is excluded because
  of Scruples / HT-DEV v1 proximity). Yes = clearly morally wrong (label 1). Group = first 6 normalized words.
- **`eth_deon` (Noul):** yes = the excuse is reasonable (label 1). State: scenario and excuse. Group = scenario.
- **`eth_just` (Noul):** yes = the claim is reasonable (label 1). Group = normalized text before " because " (else
  the first 8 words).
- Each Noul family: target 1,200, exactly 50 / 50 by hash-order downsampling. The virtue subset is not used (1:10
  construction imbalance).

### 2.3 PRM800K

- Exclude quality-control and initial-screening samples, `finish_reason ∈ {bad_problem, give_up}`, human-written
  completions and every rating-0 step (neutral / ambiguous).
- Walk the chosen trajectory. **No** candidate: the first step rated −1. **Yes** candidates: steps rated +1 before the
  first −1 (or in fully correct solutions). State: problem, previous steps (numbered), latest step.
- **Group = normalized problem text.** Per group at most one yes and one no row. Step-index buckets
  {0, 1, 2, 3–4, 5–7, ≥ 8}: yes and no counts are equalized per bucket (surplus dropped in hash order), so step
  position carries no label information. Target 4,000.

### 2.4 VitaminC

- `revision_type = real` only (the synthetic rows derive from FEVER and are excluded). SUPPORTS → yes, REFUTES → no;
  NOT ENOUGH INFO excluded.
- **Contrastive twins first:** a `case_id` with both a SUPPORTS and a REFUTES row contributes one of each (the same
  claim, different evidence), so claim-only prediction is at chance by construction. **Group = Wikipedia `page`.**
  Twins in hash order to target 4,000 rows; rows exactly 50 / 50.

### 2.5 KB-BoolQ, IndoNLI, Allegro

- **`kob_boolq` (Noul):** question in the instructions, passage in the state; yes = label 1. Group = normalized
  passage. All rows, then exact 50 / 50.
- **`indonli` (Noul):** premise and hypothesis in the state; yes = entailment (`e`), no = contradiction or neutral (in
  equal numbers). Group = `premise_id`. Target 2,500, exactly 50 / 50.
- **`allegro` (Score, 5 levels):** level = stars − 1 (non-integer ratings dropped). At most 700 rows per level in hash
  order (balanced 5 × 700 = 3,500). Group = normalized review text.

### 2.6 Common rules

- Exact duplicates (same `input_sha256`) keep one row; a normalized state seen in two groups merges the groups.
- **Development slice per source, isolated by group:** a group is DEV iff `hash("hr2-dev-v1:" + group_id) % 10 == 0`
  (split `select`, role `select`, never training). All other groups are TRAIN. DEV rows whose normalized state
  near-duplicates a TRAIN row (`v2.data.overlap self`-style E/S/L/N rules) are dropped from DEV.
- Interface mix target (TRAIN + DEV, before audits): Choice ≈ 12,500 (33%), Noul ≈ 17,100 (45%), Score ≈ 8,500 (22%);
  total ≈ 38,000 (inside the 20–60k target). Shortfalls are reported, never filled by relaxing a rule.

## 4. Blind label review (thresholds fixed now)

- **Sample:** 24 TRAIN rows per family × 11 families = **264 rows**, one row per group, stratified by gold (Noul
  12 / 12, Choice 12 / 12 by gold position, Score as evenly as possible over levels), in `hash("hr2-review-v1:" + id)`
  order. A family short of a cell keeps what it gets (reported).
- **Packets:** only what a model sees (instructions, state, option descriptions) under opaque ids
  (`hash("hr2-packet-v1:" + id)` order); no id, group, family, source, label or audit field. Keys stay on node A until
  every blind answer is in. Two packets per reviewer role (132 items each).
- **Reviewers:** fresh subagents (model `claude-opus-5-5-max`) with committed instructions
  `records/dq/reviewer-hr2.md`; R1 and R2 each answer every item independently (R2 in a different order), with a
  confidence and an optional defect flag; R3 (fresh) answers only the items where R1 and R2 split
  (`records/dq/adjudicator.md` part 1 semantics: not told why).
- **Agreement:** Choice / Noul: same answer as gold. Score (5 levels): within one level of gold (|Δ| ≤ 1).
- **Gold error:** both R1 and R2 disagree with gold, or they split and R3 disagrees.
- Limitation, disclosed: the reviewers are one model family (AI adjudication, not human annotation).
- **Pass (all must hold):** P1 pooled error ≤ 5.0% **and** exact 95% upper bound ≤ 8.0% (≤ 12 of 264); P2 population-
  weighted error (family weights = TRAIN share / sample share; stratified bootstrap 10,000) ≤ 5.0%; P3 no family with
  ≥ 5 errors of 24 (the exact lower bound first exceeds 5% at 5 / 24).
- **Fix rule (once):** F1 drop every family failing P3; re-evaluate P1 / P2 on the remaining families' reviewed rows.
  If it still fails, HR2 is published flagged **not release-safe** and not tuned further. Rows judged gold errors are
  dropped from TRAIN in any case (listed by id privately; counted in the record). Also reported: agreement of R1 / R2 /
  majority with gold, Cohen's κ, breakdowns by family / language / gold, defect flags, and exact Score distance.

## 6. How tracks use HR2 (recommendation, not a rule change)

Add `m5/hr2/hr2.train.jsonl` as **one block** by amendment or at the next milestone, against a **matched-token
control** (the same base mixture with the same number of extra tokens drawn from its own rows), screened with
**HT-DEV v2** (no FLAG vs the tier reference). HR2 DEV per family is a diagnostic readout only (never selection);
formal CSS15 decides human transfer, and items 1–8 apply.
