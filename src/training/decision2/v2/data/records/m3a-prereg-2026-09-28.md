## 2. Sets (`v2.data.m3.qualify sets`)

- **W (warm-up, 56 prompts):** RP-v2 TRAIN prompts, 16 per task type and 8 with ≥ 4,096 native tokens,
  in `sha256("m3a-warm:" + id)` order, disjoint from R.
- **R (repeat, 512 prompts):** RP-v2 TRAIN prompts, 128 per task type (Choice, Noul, Score) plus 128
  with ≥ 4,096 native tokens, in `sha256("m3a-repeat:" + id)` order.
- **S (spot check):** the eval track's node-A AutoJev predictions (`m1-adopt/autojev27`, collected with
  image `f83b1d10…`, FLA, no persisted autotune cache; gold-free seal `afba189f…`): all 231 public-231
  items, plus 128 typed-final and 128 CSS15 items in `sha256("m3a-spot:" + id)` order, taken from the
  gold-free prompt files whose SHA-256 equals the seal. Outputs on S stay on node A, are never
  uploaded and never become targets; only aggregate agreement is recorded.

## 3. Protocol

1. Warm-up process on GPU2 over W with the empty shared cache. Its post-run autotune digest is the
   frozen reference A.
2. Round 1, concurrently: P1 on GPU2, P2 on GPU3, P3 on GPU4, each a fresh container over R ∪ S.
3. Round 2: P4 on GPU2 over R ∪ S.
4. `v2.data.m3.qualify compare` writes the report.

## 4. Gates (all must pass; tolerances fixed here)

- **G1 identity:** every receipt carries the pinned model id, revision (attested), adapter
  `autojev27-native-v1`, backend `autojev-native-eager` and decision config; every process has exit
  code 0, the pinned image, the FLA path and 26,086,635,760 loaded parameters; the package and source
  tree hashes are the same in every process.
- **G2 repeat determinism:** for the pairs P1–P2, P1–P3, P2–P3 (across GPUs) and P1–P4 (same GPU,
  new process), over every question of R ∪ S: zero validity mismatches, zero argmax mismatches, and
  maximum absolute option-probability difference ≤ **1e-3** (Noul: the returned probability). Expected
  value: bitwise-identical answers. 1e-3 is 20× below the program's earlier 0.02 AutoJev repeat gate and
  an order of magnitude below the teacher's smallest per-type ECE on TS-v2 (0.020).
- **G3 frozen autotune:** no autotune entry is added or changed by P1–P4 (digest before = after = A).
- **G4 spot check (P1 vs the eval predictions on S):** identical validity on every question, argmax
  agreement ≥ 99% of answered questions, 99th-percentile per-question maximum option-probability
  difference ≤ 0.05. Bitwise agreement is not expected because the eval predictions were collected
  without a persisted autotune cache; a wrong model, template or readout would miss these bounds by far.

**Failure rule:** if any gate fails, the qualification is recorded as failed and the AutoJev path
stops (no production, no rerun). A process that produces no output because of infrastructure (for
example a container that does not start) may be restarted once, recorded.

## 5. Production (only after a pass)

- **Waves, in this order:** AJ-M = every non-A0s row of mx-v2-full-M ∪ mx-v2-short-M (84,477 = own-Lux
  waves 1 + 2); AJ-A0s = the positional-key A0s TRAIN rows (7,299; item 3); AJ-L = the L remainder
  (36,984 = own-Lux wave 3). The RP-v2 pool and wave files are rebuilt on node A with
  `v2.data.m3.waves` and must be byte-identical to the node-B files the Lux waves used.
- **Guard before every wave** (`v2.data.m3.guard`): every prompt is a TRAIN row equal to its native
  prompt; zero shared ids, row input hashes or prompt digests with SELECT700, CAL700, CAL698, every
  held-out (AHO) and sealed (SHO) slice of the v1 and v2 arms, and every gold-free eval panel prompt
  file (typed DEV / FINAL, CSS pilot, CSS15, public 231, mlx-diag). The eval track's sealed C1 files
  are custodian-only and not read by this track.
- **Shards:** `int(sha256("m3a-shard:" + id), 16) % 3` → GPU2 / GPU3 / GPU4; one process per shard.
- **Production repeat check per wave:** 128 prompts of the wave (in `sha256("m3a-prodrepeat:" + id)`
  order) produced on the two other GPUs are re-run in a fresh process on the wave's check GPU (AJ-M:
  GPU2, AJ-A0s: GPU3, AJ-L: GPU4); G2 tolerances apply; the autotune digest must stay A. A failing
  wave is withheld (recorded).
- **Conversion** (`v2.data.m3.teacher_targets`): per row, model identity, attested revision, adapter,
  backend, config / package / source hashes, the qualified runtime of its shard, and the prompt digest
  bound to the training row. Output `{id, input_sha256, teacher_probs}` (the own-Lux wave format).
  Rows AutoJev cannot answer natively (over its input limit) get no target and are counted.
- **Publication:** each wave goes to a new private revision of
  `llm-semantic-router/decision-2.0-training-data` under `m3/teachers/autojev27/`, with the targets
  file, its report (hashes, attestation, per-shard receipts) and `PROVENANCE.md` (the provenance
  caveat: AutoJev's public training reportedly used closed-model-generated SFT data; Lux stays the
  clean default; every AutoJev-distilled candidate needs a matched own-Lux-target control), announced
  in gist `02-` immediately.
