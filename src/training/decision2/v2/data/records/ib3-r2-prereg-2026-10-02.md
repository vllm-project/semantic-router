# Preregistration — IB3-r2: the maths block of IB3 with a fresh decisive review (research & data, 2026-10-02)

Commissioned by the coordinator after IB3 was published flagged NOT release-safe (`ib3-results-2026-10-01.md`: decisive
review 29 / 216; `mqa` 1 / 54, the other errors in `wpd`, `phiu` and `esci`). This record is committed and pushed
**before any IB3-r2 row is built**. Everything not changed here is IB3's prereg (`ib3-prereg-2026-10-01.md` and its
amendments 1 and 2), unchanged.

## 1. Composition

- **Core: `mqa` only.** MathQA `train` per-option yes / no with formula-verified keys. Its construction is IB3 §2
  unchanged: same pinned raw file (`mathqa/train.json`, `00e89193…`), same verification rule, same twins, cell, group,
  cap (10,000 problems in hash order) and salts, same DEV slice (`ib3-dev-v1`) and final re-balance (`ib3-final-v1`).
  The builder runs with `--families mqa`; every other family is not converted.
- **Not included:** `wpd`, `phiu` (phishing) and `esci` (coordinator decision), and every family IB3 had already
  dropped (`fdial`, `haluqa`, `fdial2`, `maud`).
- **Optional claim-level grounding: dropped before any row was built (licence).** The source has to show the evidence
  inside the row and be clearly licensed for the visible text.
  - **WiCE** (`ryokamoi/wice@ddeb6c18`): the claims are Wikipedia sentences (CC BY-SA) and the annotations are ODC-BY.
    But the evidence is text from the cited third-party websites, "archived at Common Crawl", and the `LICENSE.md` only
    says users are "bound by the Common Crawl terms of use". That grants nothing for the article text itself, so the
    licence of the visible evidence is **unclear → dropped** (IB rule: unclear or missing licence is dropped).
  - **VitaminC** and **FEVER**: Wikipedia evidence under per-article Wikipedia terms. The program already dropped both
    for that reason (VitaminC: HR2-r2 amendment 4; FEVER: IB2's source audit), and IB3-r2 keeps that ruling. HoVer
    (CC BY-SA 4.0) is already IB2's in-distribution `hover` family, so it is not a new source for IB3-r2.
  - Already excluded in IB3 §1.3: LLM-AggreFact (CC BY-ND), RAGTruth and TofuEval (NC), FaithDial and HaluEval (G4 and
    screen failures).
  - No other claim-level source with clearly licensed visible evidence was found within the time the coordinator
    allowed ("must not delay the maths block"). Grounding remains an open gap.
- **Licence registry:** `license-registry-ib3-r2.json` (MathQA `train`, Apache-2.0; problems from AQuA-RAT,
  Apache-2.0). No ShareAlike source.

## 2. IB3's findings carried over

- IB3's gold errors and screen disagreements (the ids in IB3 run `d2`'s drop list; one `mqa` review error and one
  `mqa` screen disagreement are in it) are dropped from IB3-r2 as well.
- **Rows that IB3 sampled are not reviewed again.** The IB3-r2 decisive sample skips every row **and every group** in
  IB3's stage S key (50 rows) and stage R key (216 rows). Rows IB3's reviewers confirmed stay in TRAIN.

## 3. Audits (run again, on the IB3-r2 files)

Run `r2` on node A, same image, `--network none`, CPU only, exact mirror of a pushed commit. Every IB3 §3 gate is run
again on the IB3-r2 candidates, passes and final files: **G0** Index rows (IB1 matcher, 2,000 exact and 2,000 perturbed
positive controls), **G0u** URL / host guard (500 + 500 controls), **G1** names, **G2** overlap (PI-v4 full and
quarantining, PI-ib3, DEV-vs-TRAIN; pass 1 → re-scan → pass 2 → final re-scan), **G3** C1 names, **G4** shortcut gate on
pass 2 (`state_removed`, `option_only`, `hypothesis_only` on `proposed_answer`, each ≤ majority + 0.05; failing →
IB3-r2 has no rows and stops), **G5** balance, **G6** evaluation-only guard, **G7** isolation (IB3-r2 TRAIN, IB3-r2
DEV, IB1 round-3 DEV, IB2 DEV, HS1, PN1, HR2 DEV), **G8** tokens, and the leak guard. Index rows are never trained on.
Index numbers stay out of every record.

## 4. Blind label review

- **No stage S.** `mqa` passed IB3's stage S (1 / 10) and IB3-r2 adds no family. The runner's `skip-screen` stage
  records this, carries the §2 drop list and leaves out any family that G4 drops.
- **Stage R (decisive), fresh:** IB3 §4 rules, salts, item prefix and reviewer instructions (`dq/reviewer-ib3.md`),
  with `max(18, ceil(216 / F))` = **216 `mqa` rows** (one family), skipping the §2 rows and groups. If fewer than 216
  eligible rows remain, every eligible row is reviewed. R1 and R2 answer every item (two packets each; R2 in another
  order); R3 answers only the splits. Reviewers are fresh `claude-opus-5-5-max` subagents, run in the foreground
  (`run_in_background: false`), blind to gold, source and family.
- **PASS:** the same bars: P1 pooled error ≤ 5.0% and exact 95% upper ≤ 8.0%; P2 population-weighted error ≤ 5.0%; P3
  no family whose exact 95% lower bound exceeds 5%. Gold errors leave TRAIN in any case. PASS → `release_safe: true`;
  FAIL → published flagged `release_safe: false`. Disclosed limitation: one model family adjudicates (AI review, not
  human).
