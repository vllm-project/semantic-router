## 3a. Final r2 (amendment 4)

**Rule.** A flagged group id is excluded from every recipe when any of its hits, in either pass and in any pool, is on
an evaluation / benchmark role. Those are all the PI-v4 quarantining roles except `v1_aho_*`, `a7_aho_*`,
`rights_clean_select` (SELECT700) and `rights_clean_cal` (CAL700).

- The builder takes these four patterns as `--disclose-role` (the driver's `DISCLOSED_ROLES`). It derives the
  exclusion from the private receipt's `hits`, which already carry the union of both passes.
- The manifest `rescreen` block records the rule, the patterns, and the hit roles split into excluding and disclosed.
  `check` re-derives the rule from the receipt and the manifest's patterns.
- Hit roles that exclude: `css15_goldfree`, `css15_native`, `decision_bench_v4`, `jevbench_public231`,
  `jevbench_public231_native`, `ml_parallel_dev_v1`, `mlx_diag_v1`.

## 6. Decisions and deviations

1. **Two scan passes, flags united.** The overlap tool treats a matched unit as boilerplate when it occurs in ≥ 5
   candidate groups of the same scan. Its result therefore depends on how the candidates are grouped into scans.
   - Scanning each pool alone keeps that count within one arm, as in every arm's own audit. Scanning the whole union
     counts groups across arms: a passage shared by a v1 A3 AHO item and by several H3 and V1:A3 groups is then
     excused as boilerplate.
   - The per-pool pass flags a superset of what the union pass flags (the union pass adds nothing).
   - The amendment names neither partition. The union of both passes relaxes nothing, as in the gap audit.
   - The lenient single-scan reading would remove 50,191 rows (36.0M tokens) instead of 74,404 (49.9M).
2. **Group ids across pools.** A flagged group id is removed from every pool, because v2 group ids name the upstream
   item. In practice nothing extra was removed.
3. **Caps against the fixed r2 total.** Both the source cap and the English cap use T = base + all candidates, which
   is how the amendment defines the total for the source cap.
   - A running English share would also have admitted all of H7: it reaches 59.8% after H7, then falls with H8.
   - Every source in a group is checked; r1's `take` checked only the first member's.
4. **Short order key.** The short recipes use `mx-xl-r2:short:<pool>:`, following the r1 convention. No short cap
   binds, so the order does not matter.
5. **The anchor is not kept whole.** A0s-strict loses 1,448 of 6,547 rows (22.1%). r1 took every anchor row, but
   amendment 3 removes flagged groups of every pool.
