# Preregistration — IB3: a third licence-clean breadth block for the remaining Index deficit families (research & data, 2026-10-01)

Committed and pushed **before any IB3 row is converted**, before any audit and before any row is shown to a reviewer.
Assignment: coordinator task "IB3" (cross-track note 2026-10-01 22:35), with the licence policy of 12:10 (no NC; unclear,
missing or conflicting licences dropped; clear CC BY-SA allowed with attribution), the Index policy of 10:55 (Index
numbers stay private; no tuning on Index rows) and every rule IB1 / IB2 carry (`ib1-prereg-2026-10-01.md` §1.1, §3,
§4; `ib2-prereg-2026-10-01.md` §3, §4). Worktree / branch `xunzhuo/decision-2-training-data-ib3`. IB1 and IB2 files are
not edited; IB3 imports their G0 matcher, builder helpers and review scoring and adds `v2/data/ib3/`.

**Why IB3.** The private Index gap profile of the 4B / 9B / 27B models (numbers stay private) still points at task
families that IB1 / IB2 could not cover: phishing / malicious links, grounding (claims a response makes that its source
does not support), product-search relevance, knowledge / maths multiple choice with a shortcut-robust construction, and
contracts. IB3 covers them where a source has a clear licence and labels a reader can check.

Before this commit only source metadata and licence texts, file schemas and **aggregate counts** were read: upstream
class counts; for the two URL sources, counts per URL shape cell (scheme, `www.`, path present, length bucket) and
class; for FaithDial, counts per BEGIN label set, original-response presence and first-person marker; for HaluEval QA,
counts per answer word length and final period; for MathQA, formula operation and constant counts and option-parse
counts; for MAUD, counts per data type, question and excerpt length; the Index suite manifest (benchmark list, upstream
repositories, licences) and the PhishNChips source-licence document (metadata only). **No IB3 row was rendered,
sampled or scanned.**

## 1. Source audit (done before this commit)

### 1.1 Exclusions (as IB1 §1.1 / IB2 §1.1, plus)

- **Jev-derived benchmark repositories are never sources**: the PhishNChips release (HF `AreLit/PhishNChips`) and its
  question repository (`anisselbd/jev-phishing-bench`) are the Index benchmark itself. PhishNChips draws its URLs from
  PhishTank, OpenPhish, a GitHub phishing database and Tranco domains and its emails from the Nazario corpus and its
  own synthetic text; IB3 uses none of these files, and **G0u** (§3) drops any IB3 row whose URL or host occurs in any
  suite row.
- **No third-party Decision model outputs**; **every C1 registry dataset (any split)** and the sealed directory are
  excluded; the held-out panels (PI-v4 plus the IB supplement, §3 G2) are excluded at row level.
- **In-distribution** (a train split of a dataset whose evaluation rows the Index uses; allowed only row-disjoint
  after G0; its own family): `esci` (Amazon ESCI train).

### 1.3 Considered and not admitted (reason)

- **Licence not clear:** LEDGAR (no dataset licence from its authors; the paper is CC BY-NC, the code MIT, the LexGLUE
  copy tagged CC BY 4.0 without a licensing statement — conflicting); LLM-AggreFact (CC BY-ND 4.0, and its components
  include RAGTruth, AggreFact CNN / XSum and TofuEval with NC or research-only sources; its permissive components are
  not separable from the release); phishing-email compilations (Zenodo "Phishing Email Curated Datasets", the HF
  "seven phishing email datasets", Kaggle compilations): CC BY tags over Enron, SpamAssassin, TREC, CEAS and Ling-Spam
  mail whose own terms grant no licence (IB2's rule).
- **Phishing email:** the Nazario corpus (CC BY 4.0) is phishing only and no legitimate-email corpus with a clear
  licence was found; pairing real phishing with synthetic legitimate mail is excluded (a style shortcut). **Phishing
  email stays uncovered**; IB3 covers phishing links and pages.
- **NC / ND / research-only:** RAGTruth (Index source; NC contexts), TofuEval (MediaSum research-only, MeetingBank),
  HaluEval dialogue (OpenDialKG, CC BY-NC), HaluEval summarization (CNN / Daily Mail), HaluEval general (Alpaca,
  CC BY-NC), REVEAL (CC BY-ND).
- **Labels not checkable or shape shortcut not removable:** UCI Phishing Websites (UCI 327; CC BY 4.0, but 30 coded
  features without URLs, so a reader cannot check a label); PhiUSIIL outside the shared shape cell (its legitimate URLs
  are site homepages, so any other shape is phishing-only and would teach URL shape).
- **Contracts:** CUAD and CUAD-derived sets (excluded by rule), ContractNLI (Index source).
- **Formats:** nothing imitates an Index benchmark's format or wording; no select-all-that-apply items.

Index wording reused). Every family is **Noul** (`false` "No" / `true` "Yes"). "Hash order" means ascending SHA-256 of
`"<salt>:" + <stable key>`. Normalization `v2.data.textnorm.normalize`. A rendered state over **12,000 characters** is
dropped (reported). Balancing fields live in `audit_metadata["ib3"]` (`hash_key`, `cell`). **Every family is balanced
yes = no inside every declared cell** (below), so no declared surface property predicts the label.

**Common rules (as IB1 / IB2).** Exact duplicates (same `input_sha256`) keep one row; an input with conflicting labels
is dropped entirely; a normalized state seen in two groups merges them. **DEV slice per family, isolated by group:** a
group is DEV iff `hash("ib3-dev-v1:" + group_id) % 10 == 0` (split `select`, role `select`, never training); DEV groups
near TRAIN (self-scan) are dropped from DEV. `finalize` re-balances inside every cell after every drop (a twin whose
partner is dropped goes too). Shortfalls are reported, never filled by relaxing a rule. Expected TRAIN before audits
≈ 35–45k rows (target 30–80k); phishing and grounding are capped only by their sources.

## 4. Blind label review (IB2 §4 unchanged; thresholds fixed now)

- **Stage S (screen):** 10 TRAIN rows per surviving family (one per group, gold-stratified),
  `hash("ib3-screen-v1:" + id)` order, from the pass-2 TRAIN file after G0, G0u, G2 and G4; one fresh reviewer. A
  family with **≥ 3 / 10** disagreements is dropped; every screened row the reviewer disagrees with leaves TRAIN.
- **Stage R (decisive):** a fresh sample excluding every screened row and group, `max(18, ceil(216 / F))` rows per
  surviving family (n ≥ 216), salts `ib3-review-v1` / `ib3-packet-v1` / `ib3-review-r2-order-v1` /
  `ib3-review-r3-order-v1`, item prefix `w`. R1 and R2 answer every item (two packets each, R2 in another order); R3
  answers only the splits. Reviewers are fresh `claude-opus-5-5-max` subagents with `records/dq/reviewer-ib3.md`, run
  in the foreground (`run_in_background: false`), blind to gold, source and family.
- **Gold error:** R1 and R2 both disagree with gold, or they split and R3 disagrees.
- **PASS (all must hold):** P1 pooled error ≤ 5.0% and exact 95% upper bound ≤ 8.0%; P2 population-weighted error
  ≤ 5.0%; P3 no family whose exact 95% lower bound exceeds 5%.
- **No fix rule.** Gold errors are dropped from TRAIN in any case. PASS → `release_safe: true`; FAIL → published
  flagged `release_safe: false`, and nothing more is tried in this job. Limitation, disclosed: the reviewers are one
  model family (AI adjudication).
