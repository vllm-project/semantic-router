# Preregistration — IB1: a licence-clean breadth block for the Index task families (research & data, 2026-10-01)

Committed and pushed **before any IB1 row is converted**, before any audit and before any row is shown to a reviewer.
Assignment: coordinator task "IB1" (2026-10-01), after the cross-track note of 10:55 (Index frontier goal: Index
numbers stay private, no tuning on Index rows). Binding rules also from the notes of 2026-09-30 02:25 (PN1-r2 fix
method), 2026-09-29 16:40 (typed-family and panel rules), 16:20 (C1 independence) and 23:40 (C1), the HR2 build
(`hr2-prereg-2026-09-30.md`, G1–G8, blind review) and HR2-r2's licence rule (amendment 4 §B: no NC; no ShareAlike
that is incompatible with Apache-2.0 model releases; if incompatible or uncertain, drop the source). Worktree / branch
`xunzhuo/decision-2-training-data-ib1`.

**Why IB1.** The external Index reproduction (private; numbers never leave the private directories) places the
released 2.0 models' deficits on task families that are absent from 2.0 training. IB1 adds human-labelled (or
objectively constructed) training rows for those families from sources no Index row, held-out panel or C1 registry
dataset uses, so that tracks can add them as one block against a matched control. Typed / A7 synthetic gains are
known to inflate JevArena without moving C1, so IB1 prefers human gold; the two constructed families (`snips_*`,
`poem`) take their gold from structure that a reader can check.

Before this commit only source metadata, licences, file schemas, upstream class counts and the Index suite's
manifest (benchmark list, upstream repositories and splits, question shapes) were read. No IB1 row was rendered,
sampled or scanned.

**Common rules.** Exact duplicates (same `input_sha256`) keep one row; any input with conflicting labels is dropped
entirely; a normalized state seen in two groups merges the groups. **DEV slice per family, isolated by group:** a
group is DEV iff `hash("ib1-dev-v1:" + group_id) % 10 == 0` (split `select`, role `select`, never training); DEV rows
whose group near-duplicates a TRAIN group (self-scan) are dropped from DEV. Shortfalls against a cap are reported, never
filled by relaxing a rule. Expected TRAIN before audits ≈ 70–80k rows (inside the 40–120k target).

## 4. Blind label review (two stages; thresholds fixed now)

HR2's single review found 6.0% gold errors, spread over families. IB1 therefore screens families first and decides on
a fresh, independent sample, so the decisive estimate is not biased by the screen.

**Stage S (screen).** 10 TRAIN rows per family (one per group, gold-stratified), drawn in
`hash("ib1-screen-v1:" + id)` order from the final candidate TRAIN rows after G0, G2 and G4; one fresh reviewer (S1)
answers blind with the instructions `records/dq/reviewer-ib1.md`. **A family is dropped if S1 disagrees with gold on
≥ 3 of its 10 rows** (Score: |Δ| ≥ 2). Every screened row S1 disagrees with is also dropped from TRAIN.

**Stage R (decisive).** On the families that survive, a **fresh** sample excluding every screened row and group:
`n_f = max(14, ceil(210 / F))` TRAIN rows per family (F = surviving families; one per group, gold-stratified,
`hash("ib1-review-v1:" + id)` order), so n ≥ 210. Packets carry only `rid`, `task_type`, `instructions`, `state` and
`options` under opaque ids (`hash("ib1-packet-v1:" + id)` order); keys stay on node A until every blind answer is in.
R1 and R2 are fresh subagents (`claude-opus-5-5-max`) with `reviewer-ib1.md`; each answers every item (R2 in a
different order, two packets each); a fresh R3 answers only the items where R1 and R2 split (not told why).

- **Agreement:** Choice / Noul same key as gold. **Gold error:** R1 and R2 both disagree, or they split and R3
  disagrees.
- **PASS (all must hold):** P1 pooled error ≤ 5.0% and exact (Clopper–Pearson) 95% upper bound ≤ 8.0% (for n = 210:
  ≤ 9 errors); P2 population-weighted error ≤ 5.0% (weights = TRAIN share / sample share; stratified bootstrap 10,000
  reported); P3 no family whose exact 95% lower bound exceeds 5% (for 14 rows: ≥ 4 errors).
- **No fix rule.** Gold errors are dropped from TRAIN in any case. PASS → `release_safe: true`; FAIL → IB1 is
  published flagged `release_safe: false` and nothing more is tried in this job.
- Also reported: agreement of R1 / R2 / majority with gold, Cohen's κ, splits, breakdowns by family / language /
  gold, defect flags. Limitation, disclosed: the reviewers are one model family (AI adjudication, not human
  annotation).

## 6. How tracks use IB1 (recommendation, not a rule change)

Add `m6/ib1/ib1.train.jsonl` as **one block** against a **matched-token control**, screened with HT-DEV v2, with
items 1–8 in force; item 8 needs the custodian C1 recheck first. The in-distribution families (`w2c`, `isarc`) can be
left out to measure transfer from the other families alone. Index runs on frozen packages measure the effect
privately; IB1 DEV per family is a diagnostic only (never selection).
