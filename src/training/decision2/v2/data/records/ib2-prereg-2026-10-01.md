# Preregistration — IB2: a second licence-clean breadth block for the uncovered Index task families (research & data, 2026-10-01)

Committed and pushed **before any IB2 row is converted**, before any audit and before any row is shown to a reviewer.
Assignment: coordinator task "IB2" (2026-10-01 13:40), with the licence policy of 12:10 (no NC; unclear or missing
licences dropped; **clear CC BY-SA allowed with attribution**) and every rule IB1 carries (`ib1-prereg-2026-10-01.md`
§1.1, §3, §4: Index numbers stay private, no Index row is trained on, C1 registry datasets and the sealed directory are
never read, no Jev or third-party Decision model outputs). Worktree / branch `xunzhuo/decision-2-training-data-ib2`.
IB1's worktree is not touched; IB2 imports IB1's G0 matcher and review tooling unchanged and adds `v2/data/ib2/`.

**Why IB2.** The private Index reproduction places the largest remaining deficits on tool-call decisions (call or
abstain, function choice, arguments) and phishing / spam, then stance, fact verification, knowledge MCQ, checkable
maths and contracts — families IB1 could not cover. HR2, HR2-r2 and IB1 all reached 5–6% blind-review disagreement on
crowd-labelled boundary classes, so IB2 **prefers labels a reader can check**: tool relevance and arguments by schema
and by literal grounding in the request, MCQ with verified keys, maths with checkable answers, curated spam labels,
and crowd stance only where every annotator agreed.

Before this commit only source metadata and licence texts, file schemas, upstream class counts, the Index suite's
manifest (benchmark list, upstream repositories, licences) and the protected-document term hits of §3 G1 were read.
No IB2 row was rendered, sampled or scanned.

## 2. Row construction (fixed now)

Rows follow `training.model.data` through `v2.data.sources.common.make_row` with arm `ib2` (the same helpers as IB1;
English instructions; no Index wording reused). Noul options are `false` "No" / `true` "Yes". "Hash order" means
ascending SHA-256 of `"<salt>:" + <stable key>`; "rotated" means `rotate` with seed `"ib2-rot-v1:<family>:<key>"`.
Normalization `v2.data.textnorm.normalize`. A rendered state over **12,000 characters** is dropped (reported).
Balancing fields live in `audit_metadata["ib2"]`.

### 2.1 Glaive conversations (`fc_*`)

Parsing: functions are the JSON objects after "Use them if required -" in `system` (each with a string `name` and
`description`; conversations without functions are skipped); turns split at `USER:`, `ASSISTANT:` and `FUNCTION
RESPONSE:` with `<|endoftext|>` removed. A **call** is an assistant turn `<functioncall> {"name": …, "arguments": …}`
whose arguments parse as a JSON object and whose name is a listed function. U1 / A1 are the first user and assistant
turns, U2 / A2 the second.

- **Grounded value:** a string value whose normalized text is a substring of the normalized request (≥ 1 character),
  a number that equals a number written in the request (digits with commas removed, or an English number word
  zero–twenty), a list whose every item is grounded. Booleans, objects and empty values are never grounded.
- **Refusal:** A1 has no call, contains an apology marker (`sorry`, `apologize`, `unfortunately`) and an inability
  marker (`capabilit`, `can't assist`, `cannot assist`, `unable to`, `not able to`, `don't have the ability`, `do not
  have the ability`, `can't perform`, `cannot perform`, `not equipped`, `limited to`), and no request marker (`please
  provide`, `could you provide`, `can you provide`, `could you please`, `can you please tell`, `could you tell`, `may i
  know`, `i need the`, `i need some`, `i need more`).
- **Ask-then-call:** A1 has no call and contains a request marker; A2 is a call.
- **Slots.** Each normalized U1 is assigned to exactly one family by `hash("ib2-glaive-slot-v1:" + U1) % 4` (0 `fc_rel`,
  1 `fc_sel`, 2 `fc_args`, 3 `fc_ready`), so a request never appears in two families. Group = `glaive:` + normalized
  U1; at most 2 rows per group and family (hash order).

| Family | State → question → gold | Balance and cap |
| --- | --- | --- |
| `fc_rel` | {functions (the conversation's schemas, JSON), request U1} → "Can one of the available functions carry out the user's request?" → yes iff A1 is a call; no iff A1 is a refusal | yes / no equal; ≤ 8,000 |
| `fc_sel` | A1 is a call; {request U1} → "Which function should the assistant call to carry out this request?"; options = the called function and 3 others as "name: description", rotated. Distractors in hash order from the pool of Glaive function names (most frequent description per name) that share **no content token** with the called function's name and none with the request (tokens of `_` / camelCase splits; generic verbs and nouns excluded: get, set, create, calculate, check, find, search, generate, convert, add, update, delete, list, send, book, make, fetch, retrieve, analyze, track, schedule, play, translate, recommend, suggest, info, information, details, data) and are not listed in the conversation | gold position band; ≤ 8,000 |
| `fc_args` | A1 is a call with ≥ 1 argument, **every argument grounded in U1**; {function (schema JSON), request U1} → "Which arguments should the assistant pass to this function to carry out the request?"; options = 3 argument objects (JSON), rotated: the gold, and two copies in each of which one argument value is replaced by a value of the same parameter and type from another Glaive call of the same function name that is **not grounded in U1** (parameters in hash order, a second parameter for the second copy when there is one) | gold position band; ≤ 8,000 |
| `fc_ready` | {function (schema of the function called), request U1} → "Does the user's request already contain every required argument for this function?" → yes iff A1 is a call whose required arguments (schema `required`, else every argument) are all grounded in U1; no iff ask-then-call where at least one required argument of A2 (a number, or a string of ≥ 3 characters) is **not grounded in U1 and grounded in U2** | yes / no equal; ≤ 8,000 |

**Common rules (as IB1).** Exact duplicates (same `input_sha256`) keep one row; an input with conflicting labels is
dropped entirely; a normalized state seen in two groups merges them. **DEV slice per family, isolated by group:** a
group is DEV iff `hash("ib2-dev-v1:" + group_id) % 10 == 0` (split `select`, role `select`, never training); DEV groups
near TRAIN (self-scan) are dropped from DEV. Shortfalls are reported, never filled by relaxing a rule. Expected TRAIN
before audits ≈ 60–75k rows (target 40–120k; tool calls are the largest block by design).

## 4. Blind label review (IB1 §4 unchanged; thresholds fixed now)

- **Stage S (screen):** 10 TRAIN rows per family (one per group, gold-stratified), `hash("ib2-screen-v1:" + id)`
  order, from the pass-2 TRAIN file after G0, G2 and G4; one fresh reviewer. A family with **≥ 3 / 10**
  disagreements is dropped; every screened row the reviewer disagrees with leaves TRAIN.
- **Stage R (decisive):** a fresh sample excluding every screened row and group, `max(18, ceil(216 / F))` rows per
  surviving family (n ≥ 216), salts `ib2-review-v1` / `ib2-packet-v1` / `ib2-review-r2-order-v1` /
  `ib2-review-r3-order-v1`, item prefix `u`. R1 and R2 answer every item (two packets each, R2 in another order); R3
  answers only the splits. Reviewers are fresh `claude-opus-5-5-max` subagents with `records/dq/reviewer-ib2.md` (IB1's
  instructions with IB2's task list), run in the foreground (`run_in_background: false`), blind to gold, source and
  family.
- **Gold error:** R1 and R2 both disagree with gold, or they split and R3 disagrees.
- **PASS (all must hold):** P1 pooled error ≤ 5.0% and exact 95% upper bound ≤ 8.0%; P2 population-weighted error
  ≤ 5.0%; P3 no family whose exact 95% lower bound exceeds 5%.
- **No fix rule.** Gold errors are dropped from TRAIN in any case. PASS → `release_safe: true`; FAIL → published
  flagged `release_safe: false`, and nothing more is tried in this job. Limitation, disclosed: the reviewers are one
  model family (AI adjudication).
