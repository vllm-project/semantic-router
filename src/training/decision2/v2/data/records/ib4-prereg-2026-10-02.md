# Preregistration — IB4: licence-clean data for the Index gap families at every size (research & data, 2026-10-02)

Committed and pushed **before any IB4 row is converted** and before any audit. Assignment: coordinator task "IB4"
(2026-10-02), with the server-only directive of 12:40 (downloads, conversion, dedupe, audits and uploads run on node A;
only small summaries and text records on the workstation), the licence policy of IB1–IB3 (no NC / ND / research-only;
unclear, missing or conflicting licences dropped; CC BY-SA allowed with attribution), the Index policy (Index numbers
stay private; no tuning on Index rows; never Jev data or a Jev-derived repository) and every rule IB1–IB3 carry
(`ib1-prereg-2026-10-01.md` §1.1, §3; `ib2-prereg-2026-10-01.md` §3; `ib3-prereg-2026-10-01.md` §1.1, §3). Worktree /
branch `xunzhuo/decision-2-training-data-ib4`. IB1–IB3 files are not edited; IB4 imports their G0 / G0u matchers and
builder helpers and adds `v2/data/ib4/`.

**Why IB4.** The private Index gap profile of the 2B–27B models (numbers stay private) has a common set of deficit
families: grounded-answer faithfulness (RAGTruth-like), phishing / scams, stance (VAST-like), intended sarcasm,
entity-level financial sentiment, when to call a tool, smart-home handling and grade-school maths; the small sizes add
continuation choice, per-candidate tool selection, contract inference and hard knowledge multiple choice. IB4 adds
licence-clean training data for these families **in phases**: phase 1 (this record) for the families with a clean,
already-pinned or newly pinned source; phase 2 later, under an amendment, for the rest where a clean source exists.

Before this commit only source metadata and licence texts, file schemas and **aggregate counts** (upstream class counts,
label spellings, answerable / unanswerable counts, tool-count and target-shape counts) were read. **No IB4 row was
rendered, sampled or scanned.**

**Coordination rules applied.** No family imitates an Index benchmark's format: every IB4 family asks its own question
over its own state shape (no Index instruction, option text or state layout is copied). IB1 `sentfin` (2-class, no
neutral) is not reused; IB4 rebuilds the family entity-level with neutral (`sentfin3`). In-distribution families (train
splits of an Index benchmark's own source) are named, carried in their own family and separable by `family`.

### 1.3 Considered and not admitted (reason)

- **RAGTruth** itself: contexts carry non-commercial terms. **Claim-level grounding corpora** re-checked: none with a
  clear commercial-compatible licence beyond IB3's FaithDial / HaluEval (already used).
- **Phishing e-mail**: no licensed corpus of legitimate e-mail found; the SMS corpus is the clean substitute. Synthetic
  e-mail would need a generation run (phase 2 candidate only if a licence-clean seed and an allowed model are pinned).
- **VAST / FinEntity / HellaSwag originals**: no licence or NC. VAST-like 3-way stance needs a neutral class (Perspectrum
  has two); phase 2 candidate.
- **ContractNLI**: train emptied by G0 / G2 in IB2; CUAD protected; LEDGAR licence conflicting. Dropped.
- **Home appliances**: the Index rows come from the kit's own generator; any smart-home construction risks imitating it.
  Dropped unless phase 2 finds a distinct, non-imitating construction.
- **GSM8K-like maths, HellaSwag-like continuation, MMLU-Pro / GPQA-like**: phase 2 candidates (checkable generated maths
  from an Apache-2.0 generator; continuation and per-option twins need a G4-robust construction).

## 2. Row construction (fixed now)

### 2.0 Dedupe against IB1–IB3

Before balancing, a candidate is removed if (a) its normalized set of state leaves equals that of any row of the IB1-r3,
IB2 or IB3-r2 TRAIN / DEV files, or (b) its declared key leaf (`smish` message, `w2c_act` request, `fc_pick` request)
equals any normalized state leaf of those files. Leaf overlaps of ≥ 6 tokens that remain are counted and disclosed.

### 2.1 Families

- **`sqa2`** (Noul, twins). State {passage, question, answer}. Per answerable SQuAD 2.0 train question: the gold answer
  (yes) and, from the same passage, another question's gold answer of the same kind (number / text) that neither
  contains nor is contained in any gold answer (no). Both answers are passage spans. Cell = question id; group = article
  title; at most 20 questions per title, 4,000 questions in hash order.
- **`smish`** (Noul). State {message}. yes = the publishers' `Smishing` class, no = `ham`; their `spam` (advertising)
  and lower-case `smishing` rows are left out. Messages with < 3 words or an IPv4 address are dropped. Balanced inside
  word-length cells.
- **`isarc2`** (Noul). State {text}. The author's own `sarcastic` label; language × word-length cells.
- **`sentfin3`** (Choice-3, fixed order negative / neutral / positive). State {headline, entity}. Every (headline,
  entity) decision whose entity appears in the headline; equal per class, at most 3,000 per class.
- **`w2c_act`** (Choice-3 call / ask / decline). State {tools, request}. Single-user-turn rows with ≥ 1 tool; the
  publishers' target (SFT) or chosen response (preference) is categorised: a `<TOOLCALL>` whose names are all listed →
  call; a question or request for details without an apology → ask; an apology or inability statement without a
  question → decline; anything else dropped. Tool-count cells; at most 3,000 per class.
- **`fc_pick`** (Noul, twins). State {functions, request, candidate}. Conversations listing ≥ 2 functions whose first
  assistant turn calls one: candidate = the called function (yes) and one other listed function (no). One twin pair per
  request group; balanced per candidate name (the name alone is at chance); cap 8,000.

All families: states over 12,000 characters dropped; exact duplicates removed; groups sharing a normalized state merged;
DEV = groups with `sha256("ib4-dev-v1:" + group) % 10 == 0`, role `select`. `finalize` only removes rows and re-balances
every declared cell (salt `ib4-final-v1`).

## 3. Isolation and audits (gates; results as counts and hashes only)

All on node A, CPU only, pinned image, `--network none`, exact mirror of a pushed commit (`v2/data/ib4/node_a.sh`).

- **G0** Index-row guard (IB1 method: rules E / N1 / N2 / 13-gram over every suite row; any hit drops the whole group;
  positive controls 2,000 exact + 2,000 perturbed must all be flagged). **G0u** URL / host guard (IB3).
- **G2** overlap vs PI-v4 (full and quarantining), a PI-ib4 supplement (gold-free panels, CAL698, HR2 / PN1 / IB1 /
  IB1-r3 / IB2 / IB3-r2 DEV) and DEV-vs-TRAIN; quarantine lists applied.
- **G1** source names in protected documents (known lineage listed in `ib4/audit.py`); **C1 names** scan of raw and
  candidate files.
- **G4** shortcut audit per family on pass-1 TRAIN (`state_removed`, `option_only`, `hypothesis_only` ≤ majority +
  0.05; hypothesis fields: `sqa2` answer, `sentfin3` entity, `w2c_act` tools, `fc_pick` candidate). A failing family
  is removed from the phase.
- **G5** balance (equal rows per label overall and in every cell), **G7** isolation, **G8** token sizes, leak guard.
- **IX1 contamination audit** (row level, `v2.eval.ix1.contamination`) of final TRAIN + DEV against the full private
  Index panel (`ix1/panel-3`), planted control 200 / 200 required. Any `duplicate` or `item` row → its group is dropped
  and the phase is re-finalized.
- **Final rescan**: G0, G0u and C1 names again on the final files; must find nothing new.
- **C1 content recheck**: a spec `v2/eval/sealed/c1-recheck/r3-ib4p1.json` is prepared and `--verify-only` run by this
  worker; the keyed run is requested from the eval custodian (the data worker does not hold the C1 key). Until it passes,
  the phase is published as **"release-safe pending C1"**.
- **Review**: no blind R1/R2/R3 review this round (not in the assignment's mandatory list; no reviewer subagents). An
  author spot-check of 12 rows per family is read on the node and disclosed as such. Label quality rests on the
  publishers' labels and the deterministic constructions above.

## 5. How tracks use IB4 (recommendation)

Mix by family; keep in-distribution families (`isarc2`, `w2c_act`) separable so an arm can report with and without
them. `sentfin3` replaces IB1 `sentfin` for future arms.
