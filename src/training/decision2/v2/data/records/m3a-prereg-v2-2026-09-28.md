# M3a preregistration v2 — AutoJev-27B re-qualification and production (2026-09-28)

Committed before any v2 process runs. Ordered by the coordinator at 20:15 UTC+8 after qualification v1
([result](m3a-autojev-qualification-2026-09-28.md)) failed only its frozen-autotune gate G3 because the
warm-up had no long prompt. Everything not changed here is as in [v1](m3a-prereg-2026-09-28.md) and
[amendment 1](m3a-prereg-amendment-1-2026-09-28.md). Qualification v1 stays recorded as failed.

## Changes to the qualification

- **Runtime:** unchanged (weights `6f5b557e`, `inference.autojev27`, source `ee63c151`, image
  `f83b1d10…`, FLA, `TRITON_CACHE_AUTOTUNING=1`), with a **new, empty** shared cache
  `/data/dev2/runs/data/m3a2/triton-cache-autojev-nodeA`. The launcher now waits up to 2 minutes for a
  GPU's memory to be released before refusing it.
- **Warm-up W2 = W + length ladder.** W is the v1 warm-up (48 RP-v2 TRAIN prompts). The ladder
  (`v2.data.m3.qualify ladder`) adds 74 synthetic prompts: the first Noul and the first Choice RP-v2
  TRAIN row in `sha256("m3a-ladder:" + id)` order, with the state replaced by `{"notes": …}` holding its
  own serialized state repeated and cut to 1,200, 2,400, …, 45,000 characters. The longest exceed the
  native 8,192-token limit on purpose (invalid, not truncated). Ladder outputs only tune kernels and are
  discarded. This tunes every sequence-length bucket of the FLA `l2norm`, norm-gate and conv kernels
  (keys include `NB = ceil(tokens × heads / 65,536)`) up to the input limit.
- **New gate G0 (warm-up coverage):** the answered warm-up prompts, by the collector's own
  `input_tokens`, cover every 512-token bin below 7,680 and reach ≥ 7,680 tokens. If G0 fails the
  qualification fails.
- **R, S, protocol, G1–G4 and tolerances unchanged:** R (393) and S (487 items, 910 questions in R ∪ S)
  rebuilt by the same rule into a new directory, and they must be byte-identical to v1 (`c1d6d922…`);
  warm-up on GPU2, then P1 / P2 / P3 concurrently on GPU2 / 3 / 4, then P4 on GPU2. G2: zero validity or
  argmax mismatches and maximum option-probability difference ≤ 1e-3 for P1–P2, P1–P3, P2–P3, P1–P4.
  G3: no autotune entry added or changed after the warm-up. G4: validity identical, argmax agreement
  ≥ 99%, p99 drift ≤ 0.05 against the eval track's node-A predictions.
- **Failure rule:** any of G0–G4 fails → recorded as failed, no production, no further attempt in this
  milestone. The infrastructure-restart clause of v1 is unchanged.

## Production (only after a pass)

- **Waves, in order:** AJ-M = 84,523 prompts (M recipes, `a894651e…`), AJ-A0s = 7,299 prompts built from
  the **pk1** A0s rows (`m3/pk1/A0s/train.jsonl` `35c1f98f…`), AJ-SL = 37,219 prompts (S and L minus M,
  `87a6bca4…`). AJ-M and AJ-SL rows come from `mx-v2-all.rows.jsonl` (`16a65107…`), which must have zero
  construction-order option keys (checked with `v2.common.option_keys --check` before the first wave).
- **Node:** every AutoJev file is produced on node A GPU2–4 with the qualified runtime and cache. Node B
  GPU7 is not used: a second node would need its own qualification, and per the eval track's same-node
  finding it would not reproduce node A bit for bit.
- **Per wave** (`v2/data/m3/produce_nodeA.sh`): guard as v1 §5; three hash shards on GPU2 / 3 / 4; a
  128-prompt production repeat check of prompts produced on the other two GPUs, run in a fresh process on
  the check GPU (AJ-M GPU2, AJ-A0s GPU3, AJ-SL GPU4), G2 tolerances, autotune digest unchanged; conversion
  (`v2.data.m3.teacher_targets`), which also refuses any shard whose autotune digest changed. A failing
  step withholds the wave and stops the queue.
- **Outputs and publication:** `m3/teachers/autojev27/rp-v2/{aj-m,aj-sl}.*` and
  `m3/teachers/autojev27/pk1/A0s-train.*` — `targets.jsonl` (`{id, input_sha256, teacher_probs}`),
  `attestation.jsonl` (per row: model id, attested revision, adapter, backend, config / package / source
  hashes, prompt digest, shard, GPU, image), `report.json` (hashes, guard, shard receipts, repeat check,
  provenance caveat), plus `PROVENANCE.md` and, with the first wave, the qualification report. Each wave
  is a new private revision, announced in gist `02-` immediately.
