- **Incumbent: DEV2.0-27B = A20r** (`main` `4e89288d`, the BF16-resident runtime revision of `53233103`: same weights,

- **M5 evidence** (`m5-results-2026-09-30.md`):

    −0.56; item 4 failed (mlx-diag card-eligible −.013 [−.024, −.002]); 10 of 15 human tasks lower.
  - The adapter keeps the human transfer that full fine-tuning loses: HT-DEV v2 L128 − FF20 +.039 [+.021, +.057].
  - **New diagnosis (this worker, node A CPU, from the stored scored mlx-diag files; internal, selects nothing):**
    L128's mlx-diag Noul loss is a PAWS-X **yes-bias**. Yes-rate on gold-no pairs .200 → .294 (A20r → L128) and on
    gold-yes pairs .931 → .974; accuracy lower in 6 of 7 languages. This is the failure mode that sank 9B K5-a12's
    item 4, and the 9B track's PN1-dev guard tracks it where MLX-DEV does not (COORDINATION 2026-09-30 20:15).
- **Design logic.** Keep L128's capacity (the typed margin that item 1 needs), add breadth data for human transfer and
  the Index deficit families, add **no** typed dose, and screen the PAWS-style yes-bias in development with a guard
  validated on L128 itself.
- **Why rank 128 and not A20r's rank 32.** The paired v3 interval is dominated by H (15 tasks). A rank-32 arm keeps
  T ≈ .896, so all of item 1 would have to come from H (roughly +.03 at the median task), a gain no 27B lever has shown
  (A7 dose, HS1, PN1, full fine-tuning, teachers). Rank 128 keeps L128's typed margin (+.052) and lets the breadth block
  supply the missing H. The A20r recipe at rank 32 is still the successor reference.

## Candidates and development gates

- Each arm's candidate is the exact uniform soup of its two seeds' BEST adapters (`v2.27b.lora_soup`, exact rank-256
  concatenation, α 512; max relative deviation ≤ 1e-6). An arm with a stopped seed has no candidate (no single-seed
  candidate, no rerun).
- **Readout per candidate** (node B, aux GPU): M5's (`m4b/run_readout.sh`, `CHECKPOINT_FORMAT=peft-lora/1`: CAL698
  kernel fit at 32K, typed DEV + CSS pilot + HT-DEV v2 with it), then the slices (PN1 dev + IB DEV).
- **Gates (all must hold to go formal; `v2/27b/m6/m6_devgates.py`):**
  1. **G1 collapse:** `m4_guard.collapse` (M4 amendment 1) against A20r, as in M5 (chance tests, modal share ≥ .95,
     one category, invalid > 1%).
  2. **G2 human transfer:** HT-DEV v2 vs A20r GAIN or TIE (Δ > −0.02; `dev_readout.htdev2_block`).
  3. **G3 typed floor:** T_dev ≥ T_dev(M5-L128) − 0.03, and Choice / Score typed-DEV accuracy each ≥ L128's − 0.03.
     The floor is the base recipe's (L128), because M6 adds no typed dose and the question is erosion by the breadth
     block; typed DEV did not predict formal typed T for this recipe (L128: T_dev .8875 < A20r .9163, formal T .948 >
     .896).
  4. **G4 Noul floor:** typed-DEV Noul (`rule_precedence`, 400 slots) accuracy ≥ L128's − 0.03, in addition to G1's Noul
     chance and modal-share tests.
  5. **G5 mlx-diag-style Noul guard (PN1 dev) vs A20r:** hop Δ ≥ −0.03 and clean gold-no Δ ≤ 0 (point estimates; the
     9B rule). Gate only if step 0 validated it; otherwise reported.
  6. **G6 breadth:** IB DEV score B_dev = macro accuracy over the IB DEV families with ≥ 50 rows; candidate − A20r
     paired group-bootstrap (2,000 draws, seed 20261001) lower bound > 0. Per-family accuracies are reported; the
     in-distribution families' DEV rows are reported separately.
  - Reported only: P_dev = 100·√(T_dev·H_pilot) and M5's proxy guard (P_dev ≥ best − 8).
- **Finalists:** every passer goes formal, **at most two per stage**. If more than two pass (not possible in stage 1),
  the order is HT-DEV v2 GAIN first, then the higher B_dev Δ vs A20r. Development results never rank candidates
  otherwise. No passer → no formal run for that stage; the stage reports development and attribution only.

## Stop rules, budget and chains

- **Per arm-seed:** preflights one-step (finite loss and gradient norm) and reload (32 SELECT rows through the inference
  path, 0 argmax changes, max |Δp| ≤ 1e-4). A failed preflight, a nonfinite loss, an OOM or a cap breach stops that
  arm-seed; it is recorded and never rerun. One restart after an infrastructure fault (exit 139, node fault) inside
  the cap, as `run_lora_arm.sh` implements.
- **Caps:** stage-1 arm-seed 16.0 GPU-h (projection from L128's 0.40 GPU-h per million tokens plus a per-row allowance;
  the data lock checks projection × 1.15 ≤ cap); stage-2 caps are set in its data lock (≤ 20.0 per arm-seed).
- **Budget (GPU-h = wall-clock × GPUs, including preflights and evaluation; hard cap 140):**

  | Item | GPU-h |
  | --- | ---: |
  | Step 0: PN1 slices of A20r and M5-L128 | 0.3 |
  | Stage 1: 4 arm-seeds (preflights 0.2 + full ≈ 12.5–14) | ≈ 55 (cap 64) |
  | Stage 1: IB1 DEV references (A20r, M5-L128) | 0.3 |
  | Stage 1: 2 candidates × (readout 0.35 + slices 0.15) | 1.0 |
  | Stage 1: ≤ 2 × (CAL698 fit + smoke + formal + mlx-diag ≈ 0.7) | 1.4 |
  | Stage 2: 2 arm-seeds | ≈ 32 (cap 40) |
  | Stage 2: readout, slices, formal, mlx-diag | 1.2 |
  | Index runs of frozen finalists (≈ 10–11 each, if run by M6) | ≤ 33 |
  | **Planned** | **≈ 124** |

  No GPU item starts if the running total plus its cap would pass 140. Drop order: a third Index run, then a second
  Index run of the same stage, then stage 2's second seed (which removes stage 2's candidate).
- **Chain rule:** drivers run from the verified mirror; anything uploaded is checked by size and SHA-256 before a
  separate launch call; liveness by container name (`d2-27b-M6-*`) or PID, never `pgrep -f`; the first log line of
  every chain is confirmed. `m6-state.md` is committed at every poll (≤ 30 min); hand-off near 5 hours; results go to
  `m6-results-2026-10-01.md` and gist 06 (no Index value anywhere public).
