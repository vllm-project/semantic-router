# ~27B track, Milestone 2: preregistration (2026-09-28)

Signed before any Milestone 2 GPU run. Scope is the coordinator's approved
Milestone 2 (about 14 GPU-hours on node B GPU5–6). Development readouts
(SELECT, CAL, typed DEV, CSS pilot, arm held-out slices) are never release
scores; JevArena v3 is post-key and reported as "post-key same-panel"; public231
is a public-subset rerun, not the official JevBench rank. Nothing is published.
Release stays HOLD unless a formal result meets the ~27B first-release bar
(post-key v3 ≥ 65.1, i.e. 90% of AutoJev-27B's 72.31; human transfer not
significantly below it; no decision type collapsed).

## F0 — the incumbent at an 8,192-token limit (same-limit control)

C0 = BEST368 (`qwen38-27b-clean-v2-full4096-r1`, `checkpoint-0000368`,
fingerprint `d9f49904…d350d2`), trained on A0 (not A0s), so it is a control and
not a release candidate.

1. CAL temperatures refit at an 8,192 inference context with the pinned fitting
   code (`v2/27b/calibrate_context.py`). All CAL700 rows are under 4,096
   tokens, so the preregistered expectation is identical logits
   (`logits_sha256`) and temperatures to C0's 4,096 calibration; any difference
   is recorded and the refit calibration is used.
2. One formal collection (typed FINAL, CSS15, public231) at `max_length=8192`,
   seal, report, and paired comparisons against (a) AutoJev-27B from the eval
   track's node B run `m2/n2-autojev27-nodeB` (COLLECT receipt `d2120211…`,
   adopted into a node B comparator directory by identity; it must reproduce
   v3 72.310 / public 200 before use) and (b) C0 at 4,096 (Milestone 1 formal
   run, v3 56.747).
3. Identity check (no GPU): on every question inside both budgets, F0 answers
   are compared with the Milestone 1 C0 formal answers (category changes, max
   and p99 probability drift). This separates the packaging effect (recovered
   over-budget inputs) from any change of inference sources.

## Arms (identical recipe; only TRAIN changes)

BEST368 recipe from `Qwen/Qwen3.8-27B@1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`:
rank-8/alpha-16/dropout-.05 LoRA on all 496 text projections (LR 2e-5), head
LR 1e-4, CE + 0.5 Brier, AdamW wd .01, warmup .05 then cosine, batch 1×16, one
epoch, 4,096 tokens, gradient checkpointing. Seeds: s1 = 20260926 (BEST368),
s2 = 20260928 (Milestone 1 seed replicate). Eight evenly spaced checkpoints
(`--save-every ceil(updates/8)`, plus the final update); update counts differ
slightly between mixtures because tokens, not rows, are matched (disclosed).

Per arm-seed: preflights exactly as Milestone 1 (token admission; one-step
with finite loss and a saved checkpoint; reload parity on 32 SELECT rows with
0 argmax changes and max |Δp| ≤ 1e-4), then the full run, then the readout.
A failed preflight, nonfinite loss, OOM or cap breach stops that arm-seed; it is
recorded and not rerun. Cap: 3.2 cumulative GPU-hours per arm-seed (3.0 per
full attempt).

Selection: the trainer's rule (SELECT700 family-macro accuracy, then Brier,
then earliest). Calibration: per-type temperatures on CAL700 at the BEST
checkpoint. The clean CAL698 revision is used for a release candidate's final
calibration once the data track publishes it (temperatures only; argmax
metrics unchanged).

## Decision rule (fixed now)

`v2/27b/contrast.py`: point metrics from the frozen scorers, paired bootstrap
(10,000 draws, seed 20260928) resampling typed-DEV item groups, CSS-pilot items
within task and AHO groups.

- Targets: M2-V → `T_dev` (typed DEV family macro; mechanism-disjoint
  transfer), M2-S → typed-DEV Score accuracy. AHO-A2, AHO-A6g/A6h, P_dev and
  per-type results are reported for every arm.
- Seed noise from Milestone 1 (C0 vs its seed replicate): σ(T_dev) = 0.0186,
  σ(Score) = 0.0477. If M2-C s2 runs, σ becomes the larger of that and
  |M2-C s1 − M2-C s2| / √2.
- **Seed-1 pass:** 95% lower bound of Δ(target) > 0, Δ(target) > 2σ, and the
  retention floors versus M2-C s1: no typed-DEV type falls by more than 3.0
  points, H_pilot falls by at most 1.5 points, CAL Brier worsens by at most
  0.010, invalid DEV + CSS-pilot answers do not increase. An arm that fails
  seed 1 stops (not rerun).
- **Promotion (two seeds):** seed-1 pass, then seed 2 of the arm and of the
  control: the seed-2 contrast has Δ(target) > 0 with the retention floors
  intact, and the pooled two-seed contrast (mean of the per-seed differences,
  jointly resampled) has a 95% lower bound > 0 and Δ > 2σ.
- **Order:** GPU6 M2-V s1 → M2-S s1; GPU5 F0 → M2-C s1. Seed 2 of the control
  and of an arm run only after that arm's seed-1 pass.

## Candidate for the formal slot (Milestone 2 item 6)

Fixed now, never chosen on v3 or public231:

- Both arms promoted → **M2-X** = A0s ∪ A2(ρ) ∪ (A6g ∪ A6h)(ρ) (same builder,
  seed and ρ; built and hashed in an amendment before training), seed s1, same
  recipe, preflights, selection and readout.
- One arm promoted → that arm's seed-1 run.
- None promoted → M2-C s1 (the A0s-based incumbent equivalent), unless a
  treatment displaces it under Milestone 1's rule (P_dev ≥ P_dev(M2-C s1) +
  max(2.0, 2σ_P) with σ_P = 0.70, no DEV type down more than 3.0 points,
  H_pilot down at most .015, invalid not increased).

The candidate's CAL is refit at 8,192 (`calibrate_context.py`), then one formal
run exactly as F0 with comparisons against AutoJev-27B (node B), F0 and C0 at
4,096. If it meets the ~27B bar, its checkpoint goes to a private HF staging
model repo with the `qwen-adapter` profile and the pinned base pre-downloaded
on node B, and the coordinator is told immediately.
