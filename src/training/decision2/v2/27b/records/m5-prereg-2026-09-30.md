## Goal, incumbent and bars

- **Goal (M5):** post-key v3 with a paired 95% lower bound > 0 against AutoJev-27B (72.133; node B kernel run
  `m2-peer-autojev27-nodeB-kernel`), and human transfer not significantly below AutoJev-27B.
- **Reference for the successor rule: M4-A20r** (post-key v3 72.360, T .8963, H .5842; scored run node B
  `/data/dev2/runs/27b/M4-A20r-soup/formal`). A20r is being released as DEV2.0-27B `main`; until that revision exists,
  its scored run stands in for "the current revision" (coordinator 07:20). Its lower bound vs AutoJev is −1.60.
- **What the goal needs.** v3 = 100·√(T·H) and **H is the median of the 15 CSS15 task macro-F1s**; the paired
  bootstrap resamples tasks, so H dominates the interval (A20r − AutoJev: ΔT +.009 (−.013, +.032), ΔH −.002 (−.030,
  +.066)). A lower bound above 0 needs roughly Δv3 ≥ +2.5 (v3 ≈ 74.6), e.g. T ≈ .95 at H ≈ .585.
- **Where T can still move** (typed FINAL families; A20r / F-b / AutoJev): constraint competition (Choice) .882 /
  .980 / 1.000; evidence join 1.000 everywhere; exception stack (Noul) .843 / .828 / .843; resource ledger (Score)
  .860 / .823 / .705.

## Levers (M4, M4b) and the design

- Capacity is the largest lever: full fine-tuning at matched tokens T +.120 over the rank-16 LoRA soup (M4b), human
  transfer level (−.007); rank 32 vs 8 at the A20 mixture T +.058 (M4). New A7 content beats repeated rows: T +.046
  (M4). Soft targets on human rows do not help (M4b, 9B M6). A LoRA merged into BF16 weights loses the update (M4b),
  so full-weight and adapter models are not combined.
- **HT-DEV v2 references (this milestone, node A, 32K, kernel path; H_dev2 = mean of nine held-out CSS15 task
  macro-F1s; paired vs A20r):**

  | --- | ---: | --- | --- |
  | DEV2.0-27B current weights (F1) | .5779 | +.0125 [−.0017, +.0261] | TIE |
  | **M4-A20r soup** | **.5655** | — | reference |
  | F-b (M4b full fine-tune) | .5527 | −.0128 [−.0301, +.0056] | TIE |
  | Eikos-27B | .5558 | −.0097 [−.0254, +.0063] | TIE |
  | AutoJev-27B | .5443 | −.0211 [−.0363, −.0064] | FLAG (formal median H is level: .587 vs .584) |

  Full fine-tuning reads TIE vs A20r (its formal H was .566 vs .584; its weak task, media ideology, is also its
  weakest HT-DEV v2 task). HT-DEV v2 tracks the formal task **mean**; peers are read with the eval track's caution.
- **Design: stack capacity + dose (+ round-2 data) with full-parameter fine-tuning; two seeds per arm; a
  storage-light LoRA arm only as a preregistered branch.** Full fine-tuning costs about 4.75e-7 GPU-h per token on
  three GPUs (M4b receipts: 10.04M tokens in 5,724 s), barely more than the single-GPU LoRA (M4: 25.0M tokens in
  ≈ 10.0 GPU-h), and it carries the larger lever. A rank-128 LoRA on A20 (expected T ≈ .91) cannot reach the
  goal at A20r's H, and 72 GPU-h do not hold three two-seed arms, so it is run only if full fine-tuning fails its
  human-transfer or typed screen (branch B1). The full-weight release path needs the `bf16z` codec being built by
  the release track (package ≈ 52 GB in BF16); this is recorded for the hand-off.

## Candidates and finalists (at most three)

- **M5-FF20** = exact uniform FP32 soup of FF20-s1 and FF20-s2 BEST (`interp_full soup`, verified to 1e-6).
- **M5-FF20H** = the same for FF20H.
- **M5-SX** = exact uniform soup of all four BEST checkpoints (FF20-s1, FF20-s2, FF20H-s1, FF20H-s2): a
  cross-mixture soup from one base and the same two head inits.
- No per-seed readout is taken (the soup is each arm's artifact, as in M4); per-seed SELECT700 comes from the trainer.
- **Development readout of each candidate** (node B, one aux GPU): CAL698 kernel fit at 32K, then typed DEV + CSS
  pilot + HT-DEV v2 in one collection with that calibration; `v2.eval.dev_readout` with `--htdev2-reference` =
  A20r's node B HT-DEV v2 collection (same cache and path). A20r's own typed DEV + CSS pilot + HT-DEV v2 are collected
  once on node B as the reference (also a cross-node check against its node A collection).
- **Development gates (all must hold to go formal):**
  1. collapse check (M4 amendment 1: chance tests where A20r is ≥ 10 points above chance, modal share ≥ .95, one
     category, invalid > 1%);
  2. **HT-DEV v2 not FLAG vs A20r** (Δ > −0.02);
  3. **typed guard:** T_dev ≥ T_dev(A20r) − 0.03;
  4. **proxy guard:** P_dev = 100·√(T_dev·H_pilot) ≥ (best P_dev among A20r and the candidates) − 8.
- Every candidate that passes goes formal (at most three). Development results never rank candidates.
- **Calibration (23:15 rule):** CAL698 temperatures (release `calibrate_frozen`, 32K, kernels) are adopted only if
  typed-DEV and CSS-pilot aggregate ECE and Brier do not worsen; otherwise T = 1. The package is frozen before its
  formal collection (`run_formal.sh` stages cal698 / adopt / package).

## Early-stop and branch rules

- **Per arm-seed:** preflights one-step (finite loss and gradient norm) and reload (32 SELECT rows through the
  inference path, 0 argmax changes, max |Δp| ≤ 1e-4). A failed preflight, a nonfinite loss, an OOM or a cap breach
  stops that arm-seed; it is recorded and not rerun. One restart from scratch is allowed after an infrastructure
  fault (exit 139, RCCL timeout, node fault), inside the arm-seed cap.
- **Caps (GPU-h, from the M4b throughput with ≈ 12% margin):** FF20 full attempt 13.5, arm-seed 14.1 (projection
  11.9); FF20H full attempt 17.5, arm-seed 18.1 (projection 15.7); L128 arm-seed 12.0.
- **G1 (budget), at ≥ 100 updates of every running full attempt:** project the milestone total from the logged
  seconds per update. If it exceeds 72 minus the remaining evaluation plan, write `STOP-FF20H` for FF20H-s2 (not yet
  launched, or stopped if running); FF20H's artifact is then FF20H-s1's BEST and M5-SX is the three-member soup.
- **B1 (branch), on M5-FF20's development readout:** if M5-FF20 fails gate 1, 2 or 3, full fine-tuning is out: FF20H
  is stopped at once (`STOP-FF20H`; running containers stopped and recorded), M5-SX is not built, and **L128** (two
  seeds, M4's LoRA template at rank 128 / α 256 on `a20`, T0 cache, caps above) is launched on node B GPU5 and node A
  GPU2. L128's soup (exact rank-256 concatenation) goes through the same gates; M5-FF20 goes formal only with a
  recorded reason. Otherwise FF20H continues and L128 is not run.
- **No finalist:** if no candidate passes the gates, no formal run is made; the milestone records the attribution only.
