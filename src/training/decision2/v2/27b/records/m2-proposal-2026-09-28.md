# ~27B track, Milestone 2: proposal (not launched)

Written at the end of Milestone 1 for coordinator/user review. Nothing here
runs until it is approved and frozen as a preregistration with exact hashes.

## Starting point

- Working LoRA runtime: pinned image, the byte-identical BEST368 pipeline, FLA
  kernels on the training path plus one shared Triton autotune cache per arm
  (reload parity ≤6e-8). The reference gated-delta path faults in backward;
  FLA without the cache is not reproducible across processes.
- The Milestone 1 winner (see `m1-results-2026-09-28.md`) fixes the start
  (`Qwen/Qwen3.8-27B` C0 lineage or `Qwen/Qwen3.5-27B`) and the recipe
  (rank-8 LoRA on all 496 projections, CE + 0.5 Brier, one epoch, batch 16).
- Frozen-backbone heads and the Gemma MoE starts are closed for this tier
  (P_dev ≤ 40.7; Gemma frozen features and eager-MoE latency both weaker).
- Main capability gap versus the same-size peer: typed Score and Noul and
  human transfer; public231 is already at the peer's level.

## Arms (template S of the shared matrix, one shared control)

All arms: fresh official start with the Milestone 1 winner's revision, same
recipe and seed, 4,096-token cap without truncation (rows over the cap are
excluded by the same deterministic filter), SELECT700 selection at fixed
checkpoints, CAL700 temperatures, one typed DEV + CSS pilot readout plus the
arm's own AHO slice. `ρ = 0.5 × admitted A0 tokens ≈ 1.79M` (Qwen3.5/3.8
tokenizer; the data track's Qwen3.5-0.8B counts are the same family).

| Arm | TRAIN | Question |
| --- | --- | --- |
| M2-C | A0 ∪ A0-resample(ρ) | shared token-matched control |
| M2-S | A0 ∪ (A6g ∪ A6h)(ρ) | does level-balanced synthetic + natural human Score data fix 27B Score without hurting transfer? |
| M2-V | A0 ∪ A2(ρ) | do verifiable counterfactual rules raise mechanism-disjoint typed T (Noul rule precedence)? |
| M2-X | A0 ∪ every passing arm at full size | release candidate |

Frozen data by hash (private dataset `llm-semantic-router/decision-2.0-training-data`):
A6g `ac94b7f4…` (HF `fcba4874…`), A6h `23440f0c…` (HF `f8c50b13…`), A2
`2cd61397…` (HF `fcba4874…`), A0 `61740be4…`. The resample and ρ-sample are
whole-group, stratified by source × type × language, seeded, frozen by content
hash before launch (shared with the data track's tooling when available).

Decision: an effect counts when the paired group-bootstrap 95% lower bound is
positive and exceeds 2σ_seed (σ_seed from Milestone 1); retention floors
(typed DEV type −3.0 points, CSS pilot −.015, CAL Brier +.010, invalid answers
not increased). M2-X is built only from passing arms, then packaged with the
adapter-preserving builder, checked for full DEV/CSS-pilot parity, and run
once on the frozen post-key same-panel runner (typed FINAL, CSS15,
public231), with AutoJev-27B as the same-size comparator.

## GPU needs

| Item | GPU-hours |
| --- | ---: |
| M2-C, M2-S, M2-V (≈5.4M tokens each, 2.1 + preflight/readout ≈ 2.5 each) | 7.5 |
| M2-X (≈7–9M tokens) incl. readout | 3.5 |
| Package parity and formal run | 1.0 |
| Contingency (one exact resume or seed repeat) | 2.0 |
| **Total** | **≈14** |

With the current node B GPU5–6 this is about 7–8 wall hours; two more GPUs
would run M2-C/S/V in parallel and cut it to about 4.
