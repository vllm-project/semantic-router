# Decision 2.0 program: how to review it

Decision 2.0 builds a family of native decision models for System One's Choice, Noul and Score interfaces (no chat
API) in six sizes: DEV2.0-0.6B, -0.8B, -2B, -4B, -9B and ~27B. Each size is compared with its own Decision 1.0 model
and the strongest same-size peers on the same evaluation panel, and is released privately on Hugging Face only after
the release gates pass. This directory is the entry point for reviewing the whole program from this repository.

## Start here

| File | What it is |
| --- | --- |
| [BRIEF.md](BRIEF.md) | The user's authoritative brief (Chinese, verbatim; credentials removed). |
| [COORDINATION.md](COORDINATION.md) | Program conventions: sources of truth, git and gist rules, compute allocation, secrets handling, release gates, cross-track decisions (newest first) and the frozen eval runners. |
| [STATUS.md](STATUS.md) | The coordinator's status page and decision log (Chinese); the same text as gist file `00-decision-2-program-status.md`. |

These three files are sanitized snapshots of the coordinator's local copies, regenerated by
[`sync_program_docs.sh`](sync_program_docs.sh) after each status update: node addresses and hostnames are replaced by
"node A" / "node B", passages the coordinator marks private are omitted (each snapshot's header says so), and nothing
else is changed. Do not edit them here.

## Review branch

- Repository `vllm-project/semantic-router`, branch `xunzhuo/decision-2-training`.
- It starts at the pinned handoff commit `be472b9575ef15d19040d7d29206aed87b480458` (branch
  `xunzhuo/decision-2-jev-arena`), which holds the inherited research and evaluation code under
  `src/training/decision2/` (benchmark, JevArena, runtime, publication, transfer, ...).
- Each workstream commits on `xunzhuo/decision-2-training-<track>` and merges into the review branch at every milestone
  boundary and after any load-bearing result. Pushed commits are never rebased or force-pushed, so the SHAs cited in
  preregistrations, run manifests and the gist stay valid.

```bash
git fetch origin
B=origin/xunzhuo/decision-2-training
git log --oneline --first-parent be472b9575ef..$B                       # integration history
git log --oneline be472b9575ef..$B -- src/training/decision2/v2/<track>  # one track
git diff --stat be472b9575ef $B -- src/training/decision2                # everything since the handoff
git log --oneline $B..origin/xunzhuo/decision-2-training-<track>        # pushed but not merged yet
```

track's `records/` holds the markdown preregistrations (frozen before launch), configs, results, failure analyses and

merged.

## Gist

The unified gist <https://gist.github.com/Xunzhuo/cd90fce0fa548616d8a4f1b2d2398dea> is the running log. Each track
owns exactly one file (table above) and keeps it concise and newest first: research basis, frozen configs, GPU-hours,
results, failures and next steps, with exact-commit links into this branch. Entry points inherited from the previous
phase include `decision-2-portable-handoff.md`, `decision2-release-status-2026-09-28.md` and `research-synthesis.md`.
Read a file with `gh gist view cd90fce0fa548616d8a4f1b2d2398dea -f <file> --raw`.

## Hugging Face assets (private)

- Models: released sizes go to the private "Decision 2.0" collection of `llm-semantic-router`; finalist candidates
  worth keeping go to private staging model repos outside the collection. Nothing is made public without a new
  explicit instruction from the user.
- Data: training arms, teacher targets and manifests are private HF dataset revisions. Raw text whose terms do not
  allow uploading even to a private repo stays in the authorized experiment environment, with its hashes and manifests
  in HF. Eval run artifacts (reports, predictions, manifests) go to a private HF dataset.
- Records in this branch cite these assets by repository and immutable revision or content hash, so a reviewer with
  access to the organization can fetch exactly what a result used.
- Never in git: weights, datasets, panel items, gold keys, credentials, node addresses.
- Storage: the organization's private tier is capped at 100 GB (no paid plan). Before any upload, check the headroom
  with `src/training/decision2/v2/common/hf_headroom.sh --node node-a --min-free-gb <upload size in GB>`. It prints
  private usage, headroom and the largest private repositories, and exits 1 if the upload would not fit (`--json` for
  scripts). Tests: `cd src/training/decision2 && python3 -m unittest v2.common.tests.test_hf_headroom`.

## Reading results

JevArena v3 numbers are labelled "post-key same-panel" because the project has seen its answers. JevBench public 231 is
reported separately by easy / standard / hard and is not the official sealed ranking. Development readouts (SELECT,
CAL, typed DEV, CSS pilot) are never release scores. The per-size release gates are in [COORDINATION.md](COORDINATION.md)
under "Full-autonomy mandate".

## Keeping private data out

[`v2/common/check_no_private.sh`](../common/check_no_private.sh) is the shared leak guard; run it on the staged changes
before every commit:

```bash
src/training/decision2/v2/common/check_no_private.sh               # staged diff (default)
src/training/decision2/v2/common/check_no_private.sh <path>...     # files or directories
src/training/decision2/v2/common/check_no_private.sh --log origin/xunzhuo/decision-2-training..HEAD  # commits to push
src/training/decision2/v2/common/check_no_private.sh --rev <rev> src/training/decision2/v2           # a pushed tree
```

It fails on IPv4 addresses, node addresses and hostnames, credential patterns and the literal values of the private
secrets file, which it reads at runtime from `~/.config/decision2/` (`nodes.env`, optional `node-names.env`,
`secrets.env`). It prints only `file:line: category`, never the matched text; `--help` lists the categories and the
few address ranges it allows. Tests: `cd src/training/decision2 && python3 -m unittest v2.common.tests.test_check_no_private`.

## Syncing the snapshots (coordinator)

Run from the coordinator worktree (on `xunzhuo/decision-2-training`, nothing staged):

```bash
src/training/decision2/v2/program/sync_program_docs.sh            # regenerate, guard, commit if changed, merge, push; prints the SHA
src/training/decision2/v2/program/sync_program_docs.sh --dry-run  # regenerate and guard only; prints the diff
```

To keep a passage of the local COORDINATION or status file out of the published snapshot, wrap it in lines containing
`<!-- private -->` and `<!-- /private -->`; the snapshot then shows a one-line omission note.
