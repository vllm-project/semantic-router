# 0.6B encoder track, Milestone 5: preregistration, part 1 (cross-soup, arm designs, promotion)

Frozen 2026-09-28 before any Milestone 5 GPU run. Milestone 5 is post-release optimization:
find a successor that clearly beats the released candidate `m4-t-a7-soup` (post-key v3 43.54)
and the tier leader GLiNER2.5-Decide (42.52). Coordinator instructions: a cross-soup of the T
and V2 soups first; then arms (a)–(c), each with three same-init seeds and a uniform soup at
matched token budgets; promotion by the calibrated proxy with the tie rule, reading typed DEV
per type, the CSS pilot and the in-distribution checks separately; at most two finalists to the
frozen formal runner. Part 2 freezes the built mixtures, teacher files and arm specs before any
arm preflight. Development readouts (SELECT, CAL, typed DEV, CSS pilot) are never release scores.

## 1. Item 1: cross-soup X (`m5-x-soup`)

Uniform float64 average of the six M4 BEST states, T s1–s3 (`5fb870da…`, `4c6b1570…`,
`dfec5bac…`) and V2 s1–s3 (`93a3b7db…`, `908586ca…`, `c4cb6a6f…`), cast back to FP32
(`soup.py`). This equals the 50/50 average of the two soups. All six seeds share the backbone
start (official Qwen3-0.6B-Base `da87bfb6`) and the head seed 20260928. Their specs differ
only in arm, seed, mixture, teacher, collapse-stop step and GPU-hour cap, which are the
declared allowed differences. Export and reload parity (drift ≤ 1e-5, 0 changed SELECT
answers), then the development readout (typed DEV 1,600 + CSS pilot 1,430, pinned scorers).
X is a finalist candidate under §4. Its weight is fixed at uniform: no weight search.

## 2. Arms (designs; built files, hashes and specs frozen in part 2)

**Shared recipe:** (a2) unchanged. Official Qwen3-0.6B-Base `da87bfb6` causal endpoints + global
query head; head seed 20260928, the same init as every M4 T/V2 seed, so all M4 and M5 seeds can
be souped. Backbone LR 1e-5, head 2e-4, warmup 10%, cosine to 1e-6. Batch 16 with padded
eight-row micro-batches (32,768-token budget). Loss CE + 0.5 Brier + 1.0 KL, the teacher term
applied only where the teacher saw the row's exact input. One epoch, BEST by SELECT
family-macro at eighths. Data-order seeds `20260928-06b-m5-s1|s2|s3`. Collapse stop: SELECT
< 350 at or after the 3/8 checkpoint.

**Matched budget:** every arm fills T's 19,999,143 tokens (whole groups, so slightly under).

**Execution:** the three seeds of an arm train concurrently on one GPU (`m5_arm.sh`). Each
process is capped at 72 GiB reserved (M4 peaks were 20–25 GiB) and a 3.0 h wall clock.
GPU-hours are the GPU's wall-clock occupancy. Concurrency changes no computation.

## 3. Candidate artifacts

- **Per arm (17:15 rule):** the uniform soup of its three seeds if the soup's P ≥ the arm's seed
  mean, otherwise the median-P seed. The soup must also pass export/reload parity.
- **Optional Z (`m5-z-soup`).** Take the M5 arm whose artifact passes the §4 floors and transfer
  guard with the highest P ≥ 28.74. Z is then the uniform soup of the three T seeds and that
  arm's three seeds. It is formed only after every arm readout, at most once.

## 4. Promotion rule (at most two formal runs in Milestone 5)

Candidates: X, the three arm artifacts, and Z.

1. **Floors (as M4e):** CSS pilot H ≥ .281, typed DEV Choice ≥ 186/800, SELECT Noul ≥ .85 and CAL
   Noul ≥ .85, and P ≥ 30.5.
2. **Transfer guard (new; the proxy mis-ranked T against V2):** the three-task CSS-pilot mean
   macro-F1 must be ≥ .355 (the T soup's .385 − .03).
3. **Finalists:**
   - Take the two candidates that pass both 1 and 2 with the highest P, each with P ≥ 28.74
     (the T soup's 32.74 − 4).
   - If the 2nd and 3rd are within the tie band (|ΔP| < 4), take the one with the higher pilot
     mean.
   - A candidate failing only the guard may take an empty slot only if P ≥ 36.74, that is,
     at least 4 above the T soup.
4. **Reported separately, never used alone to select:** typed DEV Choice / Noul / Score,
   predicted Score levels, pilot per task, SELECT and CAL per type.
5. **Formal run (`m5_formal.sh`):**
   - Frozen runner, node A, package at the 8,192-token cap (adapter `dev2-06b-causal-8k`).
   - Panels: v3, public 231, and `mlx-diag`.
   - Paired against the released `m4-t-a7-soup`, the V2 soup, Kai1, Kai1-8K, GLiNER2.5-Decide,
     Bosun 0.6B, Lex and the causal control (5,000 draws, same node).
6. **Successor rule:**
   - A finalist replaces the released DEV2.0-0.6B only if its paired post-key v3 95% CI lower
     bound against `m4-t-a7-soup` is > 0.
   - If so, it is uploaded to the private staging repo
     `llm-semantic-router/dev2-release-staging-06bm5` and reported at once, with the scored run
     directory.
   - Otherwise the released candidate stands.

## 5. Development contrasts (descriptive; `contrast.py`, 10,000 draws)

- (a) − T and (b) − T per seed index: different data orders, so descriptive only.
- (c) − (b) per seed: the same data order, so a paired teacher contrast. The teacher effect
  counts only if the lower bound is > 0 on every seed pair and the seed-mean ΔP exceeds 2σ_seed
  (matrix v1.1).

## 6. Budget and queue

- **Part 1:** the X soup and its readout, ≤ 0.05 GPU-hours.
- **Arms:** nine runs at about 0.75 GPU-hours each if run sequentially, less when they share a
  GPU. Readouts ≈ 0.3, formal runs ≤ 0.5.
- **Plan:** ≈ 5 GPU-hours on node A GPU1, plus GPU0 once the coordinator returns it. Hard cap
  7.5.
- **Queue:** GPU1 runs X, then (a), then (b), then (c). (b) or (c) moves to GPU0 if it
  returns.
- A failed preflight stops that arm, and failed arms are not rerun.
