# 0.6B encoder track, Milestone 1: preregistered arms

Frozen 2026-09-28 before any Milestone 1 training preflight or optimizer update.
Code: `src/training/decision2/v2/06b/` on branch `xunzhuo/decision-2-training-06b`.
Every node run uses an exact mirror of a pushed commit and one leased GPU
(node A GPU0–1). Development readouts are never release scores; JevArena v3
results are post-key same-panel comparisons.

## Why these arms

Evidence already on record (not rerun here):

- Kai1 v3 post-key 35.938 (`T` .361875, `H` .356907); its own clean-v2
  continuation Kai2 fell to 35.090 (Choice and Noul down, Score up).
- The official-Qwen 0.6B shared-head control reached v3 38.520 with `H`
  .480094 but `T` .309063: Choice 109/800 (constraint competition 22/400,
  evidence-join Choice 87/400 versus Kai1 59/400 and 218/400).
- On the same clean-v2 data, the Qwen control beats Kai on 12 of 15
  human-transfer tasks; Kai's 404 invalid transfer answers are almost all
  `tropes` (114/114) and `media_ideology` (252/498), both below the median.
  The Kai 1,024-token cap is a product wrapper: the native collator and
  training API accept 8,192 tokens and the backbone was trained to 8K.
- Six matched Qwen head/objective/initialization/teacher/gradient arms
  failed their SELECT gates; they are not repeated.

Hypotheses, each attributable to one change against a named control:

1. Kai lineage lost transfer because continuation used only the 6,262 rows
   that fit 1,024 tokens and hard labels that overwrite the source
   distribution. Test the 8K admission alone (K8H versus archived Kai2), then
   soft self-replay on top (K8S versus K8H).
2. Lex (Kai continued on an English typed-decision specialist mix) is a
   better Kai-lineage start than Kai (L8H versus K8H).
3. The Qwen control's transfer gain comes from a stronger pretrained
   backbone, while Kai's joint bidirectional candidate encoding helps typed
   Choice. An official, never decision-modified bidirectional encoder with
   Kai's candidate-marker layout and the Qwen control's shared candidate head
   can keep both (EB610 versus the Qwen control and K8H). mmBERT-base, Kai's
   upstream family, is the same-recipe smaller control (MB307).

## Frozen inputs shared by all arms

- Rights-clean v2 TRAIN 7,455 `61740be4…3755`, SELECT 700 `32a4352d…f2a6`,
  CAL 700 `3e34f6cb…f60a`, manifest `61aa8830…e9ee8`. Rows become System One
  requests with `training.data.build_kai06b_native_v1.convert` and the pinned
  bundle converter `system_one_training_rows` (Kai and Lex copies are
  byte-identical except a published-identity constant; tokenizer identical).
- Complete-input cap 8,192 native tokens for training and inference, no
  truncation. Every TRAIN and SELECT row must fit; if any does not, the arm
  stops before training and a whole-group quarantine is preregistered first.
- One epoch in a fixed hash order (seed `20260928-06b-m1`) identical for all
  arms; logical batches partitioned in that order.
- SELECT at step 0 and eight evenly spaced milestones. BEST: highest SELECT
  six-family macro accuracy, then lower macro half-Brier, then earlier step.
  Step 0 is eligible only for continuation arms (unchanged source).
- CAL is read only after BEST is fixed, to fit per-type temperatures as a
  calibration diagnostic. Accuracy and macro-F1 readouts use raw
  probabilities (temperature cannot change a winner).

## Preflights (each arm, before its full run)

`train --preflight`: data hashes, admission of every row under 8,192 tokens,
step-0 SELECT, one update with finite loss and gradients, export, fresh
reload, and zero category changes with ≤1e-5 probability drift on 32 SELECT
rows. For K8H the step-0 SELECT must reproduce the archived Kai2 step-0
count (377/700 under its rule) up to exact-tie differences (≥374). Encoder
sources must pass the zero-step native-shape check (Choice 2/10/255, Noul,
Score 3/10, a ~6K-token state, multi-question request). Any failure stops
that arm and is recorded.

## Development readout and promotion

The BEST export of every completed arm is read out **once** on typed DEV
1,600 and CSS pilot 1,430 with the native 8K adapter and the pinned typed
and transfer scorers. Development proxy `P = 100·√(T_dev·H_pilot)`.

Promote an arm to the formal post-key v3 + public JevBench 231 run only if:
`P ≥ max(P_Kai1@8K, P_Lex@8K, 29.02) + 2.0`; typed DEV Choice ≥ 137/800,
Noul ≥ 203/400 and Score ≥ 85/400 (Kai1 levels) with at least two Score
levels predicted; CSS pilot median macro-F1 ≥ .2810; and ≤1% invalid
answers per panel. At most one arm per family (Kai lineage, official
encoder), the highest `P` that passes. No checkpoint or arm is reselected on
v3 or public231. If no arm passes, the milestone ends HOLD with every result
recorded.

## Stop rules

Nonfinite loss or gradient, OOM, a failed preflight, or the GPU-hour cap
stops the arm; there is no retry with a changed recipe inside Milestone 1.
Failed arms are not rerun to fill GPUs.
