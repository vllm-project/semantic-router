## 1. Recipe families and data

**Families.** `m6-cx` = `cx-xl-r2-a7v1-full` (A0s-strict + A7 curriculum + v1 arms +
A7q/A7k/A7s/A7r). `m6-mx` = `cx-xl-r2-nogap-full` (A0s-strict + data v2 + v1 arms + A7 pools under
source caps + A7q/k/s/r), the v2-including contrast.

**Seed mixture** (family F, seed k ∈ {1, 2, 3}) = BASE + QKS_k + REST_{F,k}, built by
`v2.06b.m6_partition` (tokens: `qwen3-0.6b-base-native-segmented`, the trainer's unit):

- **Budget** B = 30,000,000 tokens per seed, each within 0.5%; one epoch.
- **BASE:** all 6,547 A0s-strict rows (3,888,278 tokens), identical in every seed of both families.
- **QKS_k:** the k-th of three disjoint token thirds of A7q, A7k and A7s over the rows in both
  recipes (A7q 22,394 of m6-cx's 23,530 rows; A7k and A7s all). Per pool, groups in
  sha256("m6-partition" ∥ NUL ∥ pool ∥ NUL ∥ group_id) order; seed 1 until the next group would
  pass a third, then seed 2, seed 3 the rest. Identical ids in m6-cx-sk and m6-mx-sk.
- **REST_{F,k}:** every other pool p of F gets R_k · N_p / N_rest tokens per seed, with
  R_k = B − BASE − QKS_k. One walk over the pool's groups in the same order fills seed 1, 2, 3 in
  turn (whole groups, never over target), then stops. Seeds are disjoint within a family.
- Whole groups only. Groups with a row over 8,192 tokens: none. Rows repeating an earlier input in
  a seed: none.

**Queue** (`m6_queue.sh`, one training process per GPU, image Python for every step), node A:

- **GPU0:** `m6-cx-s1` (with the m6-cx preflight), `m6-cx-s3`, `m6-mx-s2`.
- **GPU1:** `m6-cx-s2` (waits for the m6-cx preflight marker), `m6-mx-s1` (with the m6-mx
  preflight), `m6-mx-s3`.
- Each run: full training, then the typed DEV + CSS pilot readout when COMPLETE. Cap 1.8 GPU-h
  per run.
- **Preflights** on s1 of each family: load and parity, zero-step, padding parity, one update,
  export + reload. A failed preflight stops that family.
- A collapsed seed is recorded and not rerun. A family soup needs ≥ 2 non-collapsed seeds.

## 3. Candidate artifacts and selection (development only; never v3)

- **Proxy:** T_dev = typed-DEV macro family accuracy; H3 = the CSS-pilot macro-F1 mean over its
  three tasks (discourse, implicit_hate, semeval_stance); **Q = 100·√(T_dev·H3)**. P (the
  median-based M5 proxy) is reported too. Q is computed from each `READOUT.json`. From the
  rounded M5 values, Q ≈ 36.0 for T, 39.3 for V2, 40.2 for X, 40.5 for (a) and 42.6 for Z.
- **Family artifact:** the uniform soup of the family's non-collapsed seeds if its Q ≥ the seed
  mean Q, else the median-Q seed.
- **Guards for any candidate:**
  - typed-DEV Choice ≥ 255 and Score ≥ 101 (the released model's values);
  - Score predictions use ≥ 3 distinct levels;
  - in-distribution Noul: SELECT Noul and CAL Noul accuracy ≥ .85 (as M4e). Typed-DEV Noul is
    reported only: its rule_precedence slot is a constant answer for every 0.6B model.
  - Of the already-read soups, only X and Z pass: T and V2 predict 2 Score levels, and the (a)
    soup has typed Choice 254.
- **Cross-soup (greedy; membership by the development proxy only):**
  - Eligible groups: m4-t-a7 (T), m4-v2 (V2), m5-a (arm a), m6-cx, m6-mx. All start from the
    official base with head seed 20260928. M5 arms b and c are not eligible: both failed M5's
    transfer guard, and c is AutoJev-distilled. Weights are uniform per seed.
  - **S0** = the guard-passing soup with the highest Q among {Z, X, T, V2, a} and the two new
    family artifacts.
  - Then try each eligible group not in S0, in descending order of its own family-soup Q (ties by
    H3). Accept g iff Q(S+g) ≥ Q(S), H3(S+g) ≥ H3(S) − 0.010, typed-DEV Choice and Score of S+g
    each ≥ those of S minus 20 items, and the guards hold. At most 4 greedy steps.
  - Specs come from `m6_soupspec.py`, whose allowed differences are the fields in which the
    ingredients' run specs differ. It refuses ingredients that differ in family, base revision or
    head seed. Generated for T + V2 + (a), it reproduces `m5-z-soup` (same recipe, ingredients and
    state hashes; only the order of the allowed-difference list differs).

## 4. Finalists and the formal run

- **At most two finalists:** the two highest-Q guard-passing new candidates (those that contain
  m6-cx or m6-mx: the family artifacts and every soup evaluated in the greedy steps), each with
  Q ≥ Q(Z) − 4.
- **Formal same-panel run per finalist** on node A: v3 + CSS15, public 231 and `mlx-diag`.
  - Runs on the node-A kernel-equipped image with a frozen snapshot of a persisted Triton
    autotune cache (snapshot hash recorded before the first formal run).
  - Plus ONE same-settings control run of the released package. Its answers must equal the M4
    formal run of `m4-t-a7-soup`; if they differ, the finalists are compared against the new
    control run instead.
- **Paired comparisons** (5,000 draws) against the released model, Kai1 at 1K and 8K, Bosun and
  GLiNER2.5-Decide; M5 Z / X, Lex and the causal control are reported as well.
- **Successor rule:** all three must hold:
  - the paired post-key v3 95% CI lower bound is > 0 against the released model;
  - human transfer is not significantly worse (the upper bound of the paired H interval is ≥ 0);
  - no decision type collapsed.

  A successor is then staged privately (`llm-semantic-router/dev2-staging-06bm6-<name>`, profile
  `qwen-full`) and reported. Calibration is decided later under the 23:15 calibration rule: CAL698
  temperatures are adopted only if they do not worsen typed-DEV and CSS-pilot calibration.
- Everything is labelled post-key same-panel. Development readouts are never release scores.
