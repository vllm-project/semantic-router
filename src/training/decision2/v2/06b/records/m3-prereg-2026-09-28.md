# 0.6B encoder track, Milestone 3: preregistration

Frozen 2026-09-28 before any Milestone 3 training run. Coordinator decisions for
Milestone 3 (padding fix first; A0s-based A6 mixtures with the Lux1 teacher; arms
(a)–(d); at most two finalists; about 3–5 GPU-hours on node A GPU0–1) apply.
Development readouts (SELECT, typed DEV, CSS pilot) are never release scores.

## 1. Padding diagnosis already measured (probe `probe_padding.py`, commit `d87c98b94`)

Both families were rebuilt exactly as the trainer builds them (causal control
`m2-qc-s1`, bidirectional Qwen `m2-qb-s1`), and the first two logical batches' five
multi-row micro-batches were compared as one padded batch against the same rows one
at a time (loss, logits, hidden states at real tokens, every parameter gradient):

- **FP32 (math or default SDPA kernels): padded ≡ one-row** for both families: loss
  relative difference ≤ 5e-7, gradient relative L2 error ≤ 1e-4, hidden states ≤ 1e-5.
  Readout indices, padding side, attention/position handling, pooling and loss masks
  are correct.
- **BF16 autocast (as trained): every path is 5–26% (relative L2) from the FP32
  gradient**, concentrated in the attention and norm weights of layers 1–7; which path
  is worse changes with the kernel (efficient kernel: padded 9%, one-row 77% on one
  Choice micro-batch; math kernel: padded 26%, one-row 11%). The SDPA kernels alone
  are within 0.4% of FP32 on random inputs, padded or not.
- In the Milestone 2 logs every collapsed run (bidirectional Qwen with any readout,
  EuroBERT at both learning rates, padded causal control) loses 5–20× of its gradient
  norm between updates 20 and 30, when the 5% warmup reaches the peak learning rate.
  Padded QC s1 and one-row QCMB1 s1 (same order and head seed) had the same SELECT at
  update 58 (255) and 116 (247 vs 258); QC s1 was still rising (311) when the collapse
  stop ended it, and padded QCL s1 trained normally.

Working hypothesis: there is no padding defect; the stall is an optimization collapse
of the backbone driven by a freshly initialized head at peak learning rate, and BF16
rounding (different for padded and one-row kernels) decides whether and when a run
escapes. Proposed fix: train the fresh head alone first (backbone frozen for the first
10% of updates), then start the backbone schedule with its own 5% warmup.

## 2. Pilots M3a (Milestone 2 data and recipe; one factor each; collapse stop SELECT < 350 at update 175)

| Pilot | Spec | Change vs Milestone 2 | Tests |
| --- | --- | --- | --- |
| P1 | `m3a-qbw-s1` | QB s1 + backbone frozen for updates 1–47, backbone warmup 5% after | the fix on the arm that collapsed hardest (M2 QB s1: 253 at update 175, BEST 262) |
| P2 | `m3a-qbmb1-s1` | QB s1 with one-row micro-batches | whether padding explains the bidirectional collapse |
| P3 | `m3a-qcw-s1` | QC s1 (padded causal control) + the same freeze | the fix on the causal control (QC s1 padded: 311 at 175, stopped; QCMB1 s1 one-row: 372 at 175, BEST 517) |

Every pilot first passes the preflight, which now includes the padded-versus-one-row
parity gate (FP32: loss ≤ 1e-5, gradient relative error ≤ 1e-3; BF16: loss ≤ 1e-2 and
padded-vs-FP32 gradient cosine ≥ 0.95, on two eight-row micro-batches of the first
logical batch). P1 and P3 run to update 466 if they pass the stop; P2 always ends at
update 175 (diagnostic only). GPU0: P1; GPU1: P2 then P3.

Decision rules, fixed now:

- **Fix validated** if P1 passes the stop and reaches BEST SELECT ≥ 450/700 (the
  no-collapse level used in M2b). Then the freeze is the default for every fresh-head
  arm of Milestone 3, (b) runs, and (d) may run.
- **Padding attribution:** P2 hitting the stop means padding does not explain the
  bidirectional collapse; P2 passing means the one-row path helps there too. Either
  outcome is recorded; neither changes the arms.
- **Causal recipe for (a):** padded + freeze if P3 passes the stop and its BEST SELECT
  ≥ 477 (QCMB1 s1 517 minus the measured 40-answer seed noise); otherwise the M2
  QCLMB1 recipe (one-row micro-batches, no freeze), which trained on both seeds.
- If P1 fails, the fix is not validated: (b) and (d) do not run, and the M2 runs stay
  classified as unexplained collapses.

## 4. Readouts, finalists, formal runs

- Each BEST export: typed DEV 1,600 and CSS pilot 1,430 with the track's pinned scorers
  (as in Milestones 1–2). Report typed-DEV Choice / Noul / Score, Score levels
  predicted, `T_dev`, `H_pilot` and `P = 100·√(T_dev·H_pilot)` separately, per seed.
- Proxy (eval track Milestone 2 calibration): arms are ranked by mean P over seeds;
  |ΔP| < 4 is a tie; never select on `T_dev` alone or on typed Noul/Score; flag any arm
  whose `T_dev` rises while `H_pilot` falls.
- **Finalist bar (both seeds):** CSS pilot H ≥ .281, typed DEV Choice ≥ 186/800 and
  Noul ≥ 186/400 (the Milestone 2 bar). At most two finalists: the best by mean P, plus
  the next one if tied (|ΔP| < 4). The seed with the higher P is the arm's checkpoint.
- Finalists go to the eval track's frozen same-panel runner on node A (post-key v3 +
  public 231), compared with Kai1, Kai1 at 8K, Lex, Bosun, GLiNER2.5-Decide and the
  causal control. A finalist meeting the COORDINATION release gate is reported at once
  with checkpoint location and hashes and kept in a private HF staging model repo.
- Paired comparisons between arms use the matrix v1.1 rule: an effect counts only if
  the paired-bootstrap 95% lower bound is > 0 and |Δ| > 2× the measured seed noise.
