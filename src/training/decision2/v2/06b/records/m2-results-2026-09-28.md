## Findings

1. **Bidirectional official Qwen (approved arm) does not train in this setup.**
   It loads 597,103,104 parameters, passes every zero-step Choice/Noul/Score check,
   and the state placed after the markers changes candidate scores (bidirectionality
   verified). Both seeds collapse: within a request all candidate vectors become
   the same (probe cosine ≥ .9998, as for EuroBERT; MB307 .94), so the head gradient
   Σₖ(pₖ−yₖ)f(cₖ) vanishes. Neither span pooling nor a non-sink query fixes it.
2. **The stall is a training-dynamics issue of this trainer on Qwen/EuroBERT, not a
   code bug.** At update 0 padded-batch gradients match unpadded one-row passes under
   every training setting (cosine ≥ .99: masks, deterministic algorithms,
   checkpointing). Yet the archived causal control's own model also stalled in this
   trainer (QC, both seeds), while unpadded one-row micro-batches — the reference
   trainer's setting — trained both seeds (QCMB1 517/543). Padded micro-batching is
   the one identified factor; the bidirectional arms were not rerun unpadded.
3. **The Lux1 teacher helps the causal Qwen model on both seeds** (paired against the
   same order and head seed): SELECT 517 → 546 and 543 → 558; typed DEV Choice
   90 → 193 and 110 → 138; CSS pilot H .2856 → .2955 and .2802 → .2844. Seed 2
   still misses the Choice floor, so the arm is not a finalist. Typed-DEV Score
   stays constant at level 0 for every causal arm, with or without the teacher.
4. **The teacher does not help the Lex lineage** (LXL vs L8H, both seeds within
   seed noise), which stays far below the transfer floor (H ≈ .20).
5. Typed-DEV Score collapse persists everywhere; it remains a data problem (A6 not
   yet published by the research & data track).
