## Question

M11 stage 2 found that IB1-r3 + IB2 rows add breadth at 4B (transfer macro +.05 over 9 unseen families, HT-DEV v2 tie)
but, at matched tokens, displace typed rows and fail typed floors; and that the from-base recipe at 2B / 0.8B loses
typed skills. M12 asks whether breadth **added on top of** each tier's released recipe (every released TRAIN row kept)
gives a successor: 4B on LH (two IB doses), 2B and 0.8B on their released full fine-tune recipes (full retrains, not
top-ups of the released weights; M7 / M8 found top-ups cost quality).

## Data (`ops/m12/m12_data.py`, CPU, decoder image, both nodes; byte-identical builds required)

- Token unit: the trainer's head-readout encoding (`training.model.decision_model.encode`) with the **tier's base
  tokenizer**, no truncation; T = the tier's released TRAIN tokens. A row over 8,192 tokens stops the build.
- **Share arms:** IB tokens = round(share·T), whole groups (`group_id`), stratified by family in proportion to the
  family's tokens in the pool, groups in a seeded shuffle per family (seed 20261001), taken while the family stays within
  its quota (M11's `sample_groups`; never above the quota, so the realised share is slightly below the target and is
  reported). A target larger than the pool stops the build.
- **0.8B copies rule.** The IB pool (≈ 10.2M tokens at the 4B tokenizer) is ≈ 7% of the 0.8B TRAIN (≈ 138M tokens), so
  "≈ +20–25%" is not reachable with one pass. `08b-RA` takes the whole pool **three times** (≈ +22%); copy k > 1 of a row
  keeps the row except its id, which gets the suffix `~c<k>` (the trainer requires unique ids; the matrix-v1 builder's
  resample precedent). The trainer shuffles by seed, so copies are spread over the epoch. Disclosed: 0.8B sees each IB
  row three times; the other tiers once.
- Lines: released TRAIN first (byte for byte, file order), then the IB rows (IB1 then IB2, file order; copies in copy
  order). The builder reports rows / tokens per arm and family, the realised IB share, the longest row and every
  SHA-256. The data lock (a separate record) pins the outputs and writes `m12/data/READY-m12.json` on both nodes after it
  is pushed; every seed re-hashes its TRAIN (and the tier's teacher) against it.

## Development readouts and gates

Panels, all through `v2.dec.infer_dec` at 16,384 tokens, T = 1, on the node where the arm trained, with the tier's
M12 read cache (a copy of the node's M11 cache): typed DEV, CSS pilot, HT-DEV v2, Score5-typed-DEV, `hs1-dev`,
`pn1-dev`, the retention probes and the IB DEV panel (M11's, 3,339 rows, 12 families, prompts `7cf53e47…`, gold
`a69cf36d…` on node A).

- **Reference readouts.** The references' M11 readouts (4B: `4b-LH-f`, LH soup on node F, exact vs M10's stored
  readouts and vs node E; 2B / 0.8B: `2b-C0-e` / `08b-C0-e`, exact vs node F and node B) are copied into M12; the
  missing IB DEV panel of the 2B / 0.8B C0 is read on node E before the arm. 4B arms train on node F, 2B / 0.8B on node E,
  so every point is compared with its reference read on the same node.
- **Retention-probe overlap.** Each tier's probe gold is M10's gold (`5c674e35…`) minus every probe item hit (13-grams,
  `m10_probes.py overlap --kind train`) by the tier's released TRAIN **or by any row of the whole IB1-r3 / IB2 pool** (a
  superset of every arm's IB rows, so one gold per tier serves all its arms and its reference). Built on node A before
  any probe is scored; arms and references are scored on the same tier gold.
- **Gates** (`ops/m12/m12_rules.py`, per tier, vs the reference on the same node), M11's gate unchanged plus breadth:
  1. M8 eligibility: type / family / Noul floors, Score5-typed-DEV (M8s amendment 3's floor when the reference's check
     half is COLLAPSE; **watch: the 2B Score head**), HT-DEV v2 not FLAG;
  2. retention-probe macro delta CI upper bound ≥ 0;
  3. yes-bias guard: `hs1-dev` false-yes ≤ reference + .10 (and `pn1-dev` read for diagnostics);
  4. 0.8B only: HT-DEV v2 delta ≥ 0 (no development-only win; **watch: 0.8B choice floors**);
  5. **breadth: the transfer macro delta (the 9 IB DEV families outside `isarc` / `hover` / `gsm2`) ≥ 0**; the
     12-family IB DEV macro is reported.
- **Finalists:** ≤ 2 per tier; passing points with an HT-DEV v2 GAIN first, then the larger transfer delta. The rules
  run once per tier (`m12/select/<tier>-finalists.json`).
- **Optional transfer-only arm (4B).** After the 4B rules: if at least one of `4b-LHA` / `4b-LHA10` passes, the
  transfer-only variant of the first 4B finalist (`4b-LHAx` or `4b-LHA10x`, already built in the data lock) is trained
  (two seeds + soup, same recipe, on free M12 GPUs) if the budget allows. It is **report-only** (breadth attribution:
  gated and read the same way, never a finalist). If no 4B arm passes, it is not trained.
- Contrasts (report only): `4b-LHA` vs `4b-LHA10` (dose); each arm vs its reference; vs M11's `4b-LHB` (displacing vs
  additive at the same 25% dose; M11's readouts on node F).
