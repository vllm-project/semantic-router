## Question

M12–M14 added IB breadth to each tier's released recipe. Breadth held (transfer macro +.19 / +.15 / +.05 at 0.8B /
2B / 4B), but every arm lost a typed head or family floor, and additive IB costs multilingual decisions (M13: 4B
mlx-diag −.029; 0.8B fast track −.014). Self-distillation (M13) and upweighting (M14) moved the losses between heads.
M16 asks whether a point **between** the release and an arm keeps enough of the breadth while staying inside the
typed, retention, yes-bias and multilingual gates (a weight-space trade-off; the 9B track's ½ / ⅓ lines did the same).

## Development gates (per point vs its tier reference; no waivers)

`ops/m16/m16_rules.py` = M14's gates plus M15's MLX-DEV guard:

1. M8 eligibility: type floors, family floors, Noul floor;
2. Score5-typed-DEV floor (M8s amendment 3's floor when the reference's check half is COLLAPSE);
3. HT-DEV v2 not FLAG (0.8B also: HT-DEV v2 Δ ≥ 0);
4. retention-probe macro delta CI upper bound ≥ 0;
5. yes-bias: `hs1-dev` false-yes ≤ reference + .10;
6. breadth: transfer macro Δ ≥ 0 (the 9 IB DEV families outside the in-distribution `isarc` / `hover` / `gsm2`);
   the 12-family macro is reported;
7. **MLX-DEV guard: Noul-ML and Choice-ML paired 95% upper bounds ≥ 0** vs the reference (the 9B guard; COORDINATION
   00:15, mandatory for IB arms); Score-ML and M_dev reported.

## Selection rule (rules run once per tier on complete inputs)

- Eligible = passes gates 1–7. **Breadth gain = the transfer macro Δ** (transfer only: the 0.8B Index diagnostic
  found most of the breadth gain in the in-distribution HoVer family, COORDINATION 01:05).
- Ranking: larger transfer macro Δ; ties (equal to 4 decimals) → HT-DEV v2 GAIN first → smaller α.
- **Finalist 1** = the top-ranked eligible point. **Finalist 2** = the top-ranked eligible point on a different arm
  line, if any; otherwise the next eligible point on the same line. At most 2 per tier; none if no point is eligible.
- Output `m16/select/<tier>-finalists.json` (schema `dec-m16-finalists/1`), with every point's gate table.
