# JevArena authored v9 DEV12: editorial preregistration

Status: **prospective private development pilot**. This plan was written after
v8's independent blind/post-key `BLOCK_FOR_RELEASE_BENCH` verdict and before
any v9 prompt or answer key was frozen. V8's exact-key agreement did not solve
its two ablation lead-line leaks, one procurement inventory contradiction,
redundant original sources, decisive numeric cue, repeated three-active plus
five-inert long format, or Choice label concentration. V8 remains immutable.

## Fixed construction and review gates

1. Author at most 12 new scenarios, targeting four Choice, four Noul, and four
   Score. They will be DEV-only. No v7/v8 prompt text, scenario, or model result
   may be recycled as a new item. If twelve high-quality items cannot be built,
   retain fewer and report the shortfall rather than fill with templates.
2. Use three substantially different multi-document reasoning structures:
   source validity under an amendment, cross-document entity resolution, and a
   state update with effective time. Do not use three copies of a fixed
   three-current plus five-inactive document arrangement. Count a long item
   only if each claimed required source affects answer identifiability; visible
   length alone is insufficient.
3. The introduction describes the decision context, never the signed numeric
   values, winner, completion count, or an inventory of records that would
   contradict a source ablation. A static lexical audit flags digits and
   number words in introductory prose, but independent readers decide whether
   semantic cues remain. The ablation renderer removes the whole source and
   any dependent cross-reference. An ablation asks whether the original answer
   is provable; it is not a forced-answer scored item.
4. For each source called essential, a domain-valid counterfactual completion
   after source removal must yield a **different** output from another
   completion while preserving all remaining current evidence. The generated
   packet must expose neither completion nor the key. A mechanical parser must
   verify the rendered facts, rule version, source scope and answer with an
   independent oracle. Ambiguity or unverifiable provenance blocks the item.
5. Present Choice labels/hold in an answer-independent order fixed by one
   private salt. The four Choice winners should occupy at least three distinct
   positions, with no position holding more than two winners; the displayed
   option and source-list order must agree where comparable. A failure does not
   trigger salt resampling: retain the failed packet and predeclare any new
   version before a changed ordering rule. Report type labels and answer
   support without claiming a balanced release distribution from twelve items.
6. Freeze a prompt-only packet, separate private targets and proof traces, and
   gold-free source ablations with SHA-256 commitments. Test source deletion,
   stale-source non-revival, output-changing interventions, exact-case identity,
   prompt/key row alignment, and deterministic rebuild. Run focused tests and
   repository `make check`; commit code and non-raw notes with a sign-off.
7. An independent reviewer reads only the frozen prompts first, seals per-item
   answers and editorial findings, then reads only gold-free ablations and
   seals a second report. The reviewer must reject any lead-line disclosure,
   contradictory ablation wording, redundant claimed source, decorative long
   prose, repeated scenario template, practical answer shortcut, or unresolved
   rule ambiguity. Only after both seals may a separate post-key comparison
   open the private targets. Literal answer agreement alone never approves the
   panel. No FINAL labels, training, model selection, or release claims enter
   this pilot.

A `BLOCK_FOR_RELEASE_BENCH` finding sends the design back for revision. Even a
passing twelve-item DEV pilot would only justify drafting a separately
reviewed release-sized authored set; it would not itself become the sealed
JevArena axis.
