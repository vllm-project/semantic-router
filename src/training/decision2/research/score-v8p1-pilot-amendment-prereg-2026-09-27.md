# Score v8.1: prospective shortcut repair before candidate generation

**Signed design before v8.1 generation.** v8 is frozen at HOLD_SHORTCUT. This
new version keeps the same five mechanisms, 15 TRAIN / 10 SELECT complete
triplets, English-only scope, independent seed, structured and rendered oracles,
private gold-free blind packets, source isolation, and no-GPU/no-training rule.
It changes the renderers and distractors prospectively; no v8 example, key,
or adverse row is reselected for v8.1.

For numeric limits, evidence sufficiency, scoped exceptions, and long-memo
delivery, each rendered prompt must contain target and distractor cases whose
visible evidence spans all three ordinal outcomes. Target identity, scope,
time, or document authority must be used to choose the correct one. Evidence
notes become separate prose entries instead of repeated pipe-table rows.
Numeric logs carry one violating, one incomplete, and one complete lot in
every case. Scoped registers carry both signed and pending entries on every
case; an expired exact-scope entry and wrong-scope entries remain available.
Long memos include unrelated late, unconfirmed, and timely delivery records.
The dated ledger keeps all three actions and independently adds an audit of
answer-correlated action counts and target position.

Before any independent reviewer sees v8.1, the author-side audit must report
per-mechanism, per-level counts for salient status terms, target-row position,
and character length. Any perfectly predictive non-target feature is a HOLD.
The same source-disjoint and protected gold-free overlap rules apply. Only
after these mechanical checks pass should a different reviewer blind-solve
all 75 rows and adjudicate answerability, ambiguity, realism, and necessity.
The v8.1 pilot still cannot establish transfer or justify training by itself.
