# Qwen3.5 9B ROCm host-swap probe: prospective plan

This is a **not-yet-launched**, single, bounded diagnostic after the first-node [9B synthetic probe failed](qwen35-9b-rocm-synthetic-probe-result-2026-09-27.md). It tests whether the exact same no-optimizer forward/backward path also fails on the second authorized node. It does not resume training or change the original training arm's budget, selector, or HOLD status. Launch requires a fresh inventory, an exclusive idle-accelerator reservation, and separate approval after this preregistration is reviewed.

## Preflight and interpretation

At preregistration, the second node had one genuinely idle accelerator with about 0.28 GiB baseline memory and no active task reservation; its other seven accelerators carried existing workloads. The required image, 9B source snapshot and checkpoint were **absent** there. The first-node image occupies about 49.5 GB unpacked, source snapshot about 19 GB, and checkpoint about 564 MB. Both hosts reported the same kernel release and ROCm runtime version. Sufficient disk and host RAM exist, but those observations do not prove that a later GPU reservation remains free.

If byte-identical inputs, pinned image or an exclusive idle accelerator cannot be secured, record **INDETERMINATE** and do not run. If 20/20 finite iterations finish with identical trainable weights and no new native fault, report **PASS for the synthetic path on this host only**; the 9B training HOLD remains until a separate decision. Exit 139 or a matching native fault is **FAIL**, supporting a cross-host image/workload interaction rather than a first-host-only event. Timeout is **INDETERMINATE**. Preserve both prior failure logs and do not automatically repeat either probe.
