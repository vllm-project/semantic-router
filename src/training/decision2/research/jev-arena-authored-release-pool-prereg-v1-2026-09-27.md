# JevArena authored release pool: prospective v1 protocol

**Status: method frozen before release-pool authoring.** The v9–v12 pilots and
the 1,296-row template candidate are blocked from release. The v13 12-original
pilot passed a DEV native-solvability review but is short and formulaic; none
of its facts, prose, entities, or operation instances will be reused here.
This protocol is for a new, source-isolated release pool, not permission to
score a model or open any existing protected FINAL labels.

## Unit, size, and allocation

An **independent original** is a separately conceived decision situation with
its own document facts, rule and causal proof. Different names, numbers,
language translations, source substitutions, option permutations, label
renamings, and counterfactuals of that situation are one cluster. Count only
one original per cluster in the 1,200–1,480 release target required by the
frozen `jevarena-ranking/2` contract. This range gives 10,619–10,899
eligible text answers across the existing five panels before optional paired
robustness views. Do not fill a numerical shortfall with synthetic clones.

Aim for 400–490 originals in each native family, Choice, Noul and Score;
no family may have fewer than 360. Within each family, balance positive and
negative or low/middle/high outcomes, and rotate option positions. Cover at
least twelve substantive domains and nine source forms; cap any one domain at
12%, any one semantic operation at 5%, and any one source/document template at
3% of independent originals. Keep authored source families disjoint from
TRAIN, SELECT, CAL, DEV and exposed public benchmark examples. Use a prospective
domain-by-type-by-length allocation ledger, updated with rejected as well as
accepted candidates. Review the ledger before every 50-case batch.

Short, medium and long refer to complete native prompts under the pinned
tokenizer: approximately 150–600, 601–2,000 and 2,001–7,500 tokens, with a
reserved 10% context budget. Target 25–35% short, 30–45% medium, and 25–40%
long in the final pool, with all three types represented in each band. Long
documents must carry causal evidence, plausible conflicts and genuine retrieval
work; duplicated ledger rows or repeated filler do not qualify. Include
insufficient-evidence Choice cases only when an explicit native option and
complete rule make that answer valid; do not invent abstention labels for Noul
or Score. Vary temporal priority, exceptions, evidence linkage, state updates,
multi-party constraints, uncertainty, and distractor similarity.

## Candidate provenance and rights

Each original has a private immutable casebook entry: author, UTC creation
time, unique source-family ID, domain, operation, document form, language,
length target, provenance and redistribution rights for every source, rule,
structured facts, oracle implementation version, proof trace, alternative
completions demonstrating source necessity, and editorial history. Original
fictional scenarios carry an explicit author-created lineage. If a source is
adapted from external material, record its version, license, transformation,
and permitted use; never silently rebrand exposed benchmark facts as original.
Keep restricted raw material private. Public repository, gist, model card and
figures receive only aggregate counts, hashes, methods and failures.

Native output criteria are fixed per item before evidence is written. The
original and any paired view share the same decision contract and answer
vocabulary. Every Noul proposition is Boolean under that contract; every Score
target belongs to its declared ordered rubric. A separate deterministic oracle
derives the typed answer from structured source facts, never a hand-entered
target field. Two or more evidence sources and at least two inference steps
are required; each intended source must have two domain-valid alternative
completions that change a native-valid answer while the other sources stay
fixed. An apparently superseded source that cannot affect the answer fails.

For robustness, create complete-source counterfactuals, option order changes
or label renamings only when meaningful. Store parent joins and intervention
labels privately. Count them separately as paired robustness, never as new
independent questions; cluster confidence intervals by original. Do not let a
variant inherit the original answer by accident. Exclude unrealistic deletion
variants that make the native Noul or Score answer undefined.

## Mechanical preflight before any blinded packet

Freeze source code, casebook, originals, variants, native criteria, oracle
outputs, tokenizer and scorer hashes in a private append-only receipt. Run:

1. Schema and native-answer type checks on every row; independent oracle
   agreement, full contract parsing, proof and two-source necessity witnesses,
   intervention answer-change checks, output vocabulary, no missing fields or
   silent truncation. A generated target is not its own independent oracle.
2. Exact and near-text overlap against all available TRAIN, SELECT, CAL, DEV,
   prior authored versions, external source examples and exposed benchmark
   prompts. Examine shared eight-word spans, three-gram similarity, character
   similarity, and semantic/source-family duplicates. A zero lexical match is
   necessary, not proof of semantic independence.
3. Native tokenizer lengths using the exact serving adapter. Test the longest
   prompt with full criteria and output allowance. Inspect distractors,
   answer-only heuristics, first/last-record shortcuts, stable label/position
   leakage, document repetition, grammar and source plausibility.

A single native validity, provenance, exact overlap, semantic clone,
unjustified filler, or source-necessity failure holds the entire frozen batch.
Repairs create a new candidate version and new hashes; never rewrite a frozen
packet. Batch failures and exclusions remain in the private ledger and their
aggregate reasons in the public-safe report.

## Blind editorial gate and release stop rules

Only after the mechanical seal, issue independently salted and shuffled
gold-free originals to **two independent reviewers per case**. A different
reviewer receives each paired variant without its parent ID or intervention.
Reviewers directly produce a native answer, cite the decisive evidence,
assess both-source necessity, ambiguity, document realism and shortcut risk,
and seal row-level judgments and UTC hashes before seeing any author target,
join, proof, model output or other review. A stratified 15% of variants gets a
second independent review. Reviewers must disclose conflicts and cannot review
their own cases. This is a human editorial requirement for release; model-only
review is diagnostic.

An adjudicator checks hashes and chronology before opening the private key,
compares independent answers and evidence citations to the oracle, and records
each disagreement without overwriting first-pass judgments. Exclude ambiguous
or invalid cases and all descendants; an unresolved material disagreement,
unsupported target, fake source necessity, or rights uncertainty is a HOLD.
At least 1,200 eligible independent originals, all three type minima, every
allocation cap, two blind original reviews per survivor, complete provenance,
and zero unresolved material errors are required to pass. If achievable
quality is below the target, report the smaller audited pool and keep release
blocked. Do not add clones to reach the target.

Before any release model reads the new sealed prompts, freeze candidate model
revisions, adapter/scorer versions, all six-axis formula, and overlap checks.
The protected labels stay closed until predictions and manifests are frozen.
Invalid or missing responses count as failures. Publish per-type and
per-task results, paired cluster bootstrap intervals, negative findings,
provenance and limitations. Any development or preflight model score is labeled
DEV and cannot be promoted to FINAL.

## First scale feasibility batch

The first separately frozen batch will attempt **36–60 genuinely new
independent originals**, at least 12 per native family, at least 12 distinct
semantic mechanisms, nine document forms, six domains, and short/medium/long
examples. It remains a **private candidate**, excluded from training, model
selection and JevArena release ranking. The author must report actual
qualified count and reject rather than pad any missing cell. Mechanically
preflight before preparing blind packets. Passing this batch would establish
only feasibility of the workflow; it would not meet the release pool gate.
