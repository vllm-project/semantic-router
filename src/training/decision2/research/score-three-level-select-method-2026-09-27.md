# Independent three-level Score selection diagnostic: prospective method

**Status: design only.** No questions, answers, model responses, training run,
or selection score exist under this protocol. It does not authorize use of the
blocked Score v1–v4 curricula. The first eligible TRAIN curriculum must pass
its own mechanical, overlap, rights, and sealed blind editorial gates.

## Why a separate diagnostic is needed

The current rights-clean SELECT/CAL Score examples mainly test five-level
quantized medians. They do not test the three-level set and state reasoning
that failed in the 27B development audit. Reusing typed DEV1600 or human CSS
evaluation labels to choose a checkpoint would invalidate their role as
independent development diagnostics. This new set is **selection only**, never
a JevArena release axis or evidence of a final generalization gain.

## Data and review gate

Author at most 80 independently specified source cases, each with a
counterfactual triplet whose correct Score levels are 0, 1, and 2: at most
240 rows. Use four rule operations with 20 source cases each: nested
veto/waiver precedence, interval coverage with explicit endpoints,
independent-evidence quorum, and resource-allocation caps. These operations,
stories, code templates, source identifiers and lexical settings must be
independent of the approved TRAIN curriculum; a different rendering of its
cases is not independent. Balance 16 English and four Chinese source cases
per operation, with all three levels per language and group. Keep the three
variants of a source case in one analysis and overlap unit.

Freeze the casebook, separate mechanical oracle, gold-free prompt roster,
targets, source generator, scorer, native adapter, model-relevant tokenizer,
and hashes **before** any model inference. State all thresholds, endpoint
inclusivity, evidence independence and override order in the question.
Admit no truncated row. Run group-complete exact and bounded near-overlap
screens against parent TRAIN/SELECT/CAL, every attempted Score curriculum,
visible DEV/public prompts and all available gold-free sealed rosters. A
semantic overlap may remain despite this screen and must be disclosed.

A fresh gold-blind reviewer must solve every row and inspect complete
triplets without keys, then seal judgments and shortcut findings. Check
invalid or ambiguous options, formula-only count cues, option order, language
fidelity, label balance and rule inversion. Compare sealed judgments to the
oracle only after packet/review/seal hashes and chronology pass. One material
ambiguity, mistranslation, answer mismatch or group shortcut blocks the
version; repairs create a new version and leave old artifacts intact. A
qualified bilingual review is needed before making a Chinese-transfer
claim. The diagnostic can still be used for an English-only pilot if the
Chinese subset is separately withheld and clearly disclosed.

## Conditional matched training screen

Once an approved TRAIN curriculum and this diagnostic are both frozen,
preregister two arms from the **same** immutable source checkpoint: (A) new
Score curriculum plus parent TRAIN replay, and (B) parent TRAIN replay only.
Match admitted training tokens, optimizer updates, batch shape, context cap,
trainable topology, precision and seed; log any unmatched quantity before
interpretation. Keep the untouched source as a third reference. The exact
source, hashes, mixture, hyperparameters, replay sampling, runtime and
checkpoint-selection formula must be signed in a run-specific addendum
before step one. The current Qwen3.8-27B BEST368 is a possible first source,
not a selected arm under this document.

The author of the selection diagnostic cannot choose the winning run after
seeing typed DEV or CSS pilot labels. Freeze a source-relative advancement
gate in that run-specific addendum, including three-level Score improvement,
parent SELECT Choice/Noul retention, validity and calibration floors. Use
the new 80-group diagnostic and the existing parent SELECT700 to select a
checkpoint; do not use the public 231-item panel or any final gold for this
choice. Only a passing predeclared arm may receive one independent typed
DEV1600 and CSS pilot1430 assessment with paired group/task intervals.
Even a positive pilot is not a release result: the sealed authored panel,
multilingual evidence, full human transfer, same-panel competitors and
package parity remain separate gates.

Limit reuse of this small diagnostic: report every candidate arm, including
failures, and do not tune repeatedly on its exact cases. If exploratory
iterations exhaust the predeclared budget, retire this version and author a
new source-disjoint selection set before another architecture search.
