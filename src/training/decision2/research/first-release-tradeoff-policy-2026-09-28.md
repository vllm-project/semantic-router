# Decision 2.0 private first-release policy: composite gain with disclosed tradeoffs

**Status:** user-directed prospective policy for future candidates, recorded
after project-level access to JevArena v3 answer keys. It does not rewrite the
earlier pre-key gate, rescue a failed frozen arm, relabel v2 results, or turn a
post-key comparison into an untouched blind test. The existing private 0.6B
repository and its measured limitations remain unchanged.

The user's first-release priority is a substantial **overall** improvement
over the same-size Decision 1.0 model, while allowing individual Choice,
Noul, Score and human-task tradeoffs. This supersedes the earlier universal
requirement that every axis improve and that no typed family fall by more than
two absolute points **for new, separately registered candidates only**. It
does not remove the obligation to publish every axis and task, paired
uncertainty, probability quality, invalid rate or the model's actual origin.
The original gate document and results scored under it remain immutable.

For each new candidate, freeze an exact minimum v3 composite gain and the
same-size/near-size peer roster before that candidate's v3 predictions. The
threshold must be meaningful relative to the prior model, not set after
seeing v3 labels. A candidate that merely trades a large typed loss for a
small human-transfer gain does not satisfy the requested broad model-family
advance. Show Choice, Noul, Score, the four typed families, all 15 human
tasks, calibration and invalid/overlength behavior beside the aggregate;
state any material regression plainly. A paired interval crossing zero limits
the strength of an improvement claim even when the point estimate is higher.

The first-release package additionally needs an allowed **direct weight
initializer** (our own Decision 1.0 or official Qwen Base/general
Posttrained/Instruct), an exact lineage and rights record, full native
System One inference, complete same-panel v3 and separate public JevBench
231 predictions, source-overlap checks, saved-versus-downloaded package
parity, and a clean standard Hugging Face file tree with root `config.json`.
Compare to a strong size-near open model rerun under the same native protocol;
Decision Index 0.2.1 figures select peers but are not transplanted into the
JevArena ranking. The ~27B tier has no 1.0 parent and must be assessed against
qualified first-tier peers instead.

All first releases and the collection remain **private**. Model cards are
short product descriptions: owl/model-name banner, purpose, typed usage,
same-panel table, rank and model-by-task figures, limits and a compact methods
appendix. No Pareto chart or internal gate notes go into the card. The
JevArena v3 panel has already been keyed in this project; later scores are
post-key same-panel evidence. A new independent source-disjoint validation or
external same-version evaluation is needed before claiming general decision
SOTA or a performance/parameter frontier. Private staging is not evidence of
that claim.
