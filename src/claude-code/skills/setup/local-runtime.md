# Local runtime

Reached from `setup` step 5 when the classifier runs on this machine. `local.py` lives in `${CLAUDE_SKILL_DIR}/scripts/`. Every command is safe to rerun and does only what is missing. Nothing here needs sudo; if a step seems to need it, stop and tell the user why instead.

1. **Device and model.** Use the device the user picked: `cpu`, `cuda` or `rocm`. The runtime cannot use an Apple GPU (`mps`) for vela3 yet, so a Mac runs it on the CPU. The model is `vllm-sr/vela3-lite` (about 1.8 GB of weights, 2.3 GB RAM, 0.1 to 0.25 s per question on an idle x86 CPU with bf16; on a CPU without bf16, `local.py` serves in float32, measured at 0.7 to 2.4 s on a 4-core laptop; an Apple Silicon CPU is several times slower, and setup step 5 times it before anything is written). On the Custom path, when detect listed larger models under "also fits", offer them in one AskUserQuestion, and say plainly that their accuracy gain over lite is unmeasured. Done when the device and model are fixed.

2. **Preview and choose.** Run `python3 ${CLAUDE_SKILL_DIR}/scripts/local.py install --dry-run --device <device> --python <a Python 3.10+ path from detect>` and show the commands. They create the venv `~/.local/share/vsr/venv`, install torch (on CPU-only Linux from the PyTorch CPU index, which saves several GB of CUDA wheels), then `vllm-srun` from GitHub, since it is not on PyPI yet. Tell the user the download size: about 200 MB of CPU torch, or 2 to 3 GB of CUDA or ROCm torch, plus the model on first start. Then ask one AskUserQuestion: **Install and start it for this login (Recommended)**, which adds no service, so after a reboot the user starts it again with `/vsr:setup`; **Install and keep it running across reboots**, as a systemd user service on Linux or a launchd agent on macOS; or **Don't install**, which installs nothing and goes back to `setup` step 4 to pick another place. Done when the user chose.

3. **Install.** Run the same command without `--dry-run`, in the background (`run_in_background`), since it takes minutes. On failure, show the last pip lines and stop. For `rocm`, torch from PyPI is a CUDA build: if the install finishes but the runtime reports no ROCm device, point the user to pytorch.org for the ROCm wheel index. Done when `local.py install --dry-run` prints `nothing to install`.

4. **Start.** For this login only: `python3 ${CLAUDE_SKILL_DIR}/scripts/local.py start --device <device> --model <model>`. Across reboots: `python3 ${CLAUDE_SKILL_DIR}/scripts/local.py service --device <device> --model <model>` first, show the unit it prints, then rerun with `--write` once the user agrees; that writes the unit into the user's own directory and starts it. A runtime started with `start` holds the port, so stop it before switching to the service. Done when the start command exited 0.

5. **Wait for it.** Run `python3 ${CLAUDE_SKILL_DIR}/scripts/local.py wait --timeout 900` in the background. The first start downloads the model. Done when it prints `ready:`. If it times out, show the log lines it prints. A missing snapshot when offline is fixed with `--offline --base-path <snapshot>` on `vllm-srun serve`, but only suggest it if the log says so.

The runtime URL for the settings is `http://127.0.0.1:<port>/v1/decisions` (port 8790 unless the user changed it), and `runtime` is `local-cpu` for `cpu` and `local-gpu` otherwise.
