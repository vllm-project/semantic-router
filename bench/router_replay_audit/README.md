# Semantic Router Counterfactual Audit PoC v0.1

A small, **offline and implementation-independent** behavioral audit prototype for
vLLM Semantic Router.

It is intentionally read-only: it does not modify the Go router, hot path, or
routing policy implementation.

## What v0.1 demonstrates

```text
native Router Replay-shaped record
→ baseline policy reproduction PASS

official authz E2E-derived scenario
→ discrete counterfactual margin

synthetic gray-boundary fixture
→ minimal route-flip margin

synthetic stateful fixture
→ A→B != B→A

synthetic grouping fixture
→ (A★B)★C != A★(B★C)
```

`★` is **not ordinary function composition**. In the grouping fixture it is
explicitly defined as:

```text
state merge/update
→ lossy projection/reduction
→ routed state
```

That makes grouping sensitivity a real property of the defined state-reduction
operator, rather than a claim that ordinary function composition is
non-associative.

## Evidence classes

This PoC deliberately separates two evidence classes.

### 1. Official-profile-derived fixtures

`official_authz_premium_complex.json` is derived from the public Semantic Router
AuthZ-RBAC E2E profile and testcase at repository commit:

```text
8d84987b04c63cd35be211a7aa337336b071ae20
```

Relevant upstream files:

```text
e2e/profiles/authz-rbac/values.yaml
e2e/testcases/authz_rbac_routing.go
```

The upstream profile declares, among other rules:

```text
premium_user + complex_analysis → premium_complex → Qwen2.5-14B
premium_user                    → premium_default → Qwen2.5-7B
```

The official testcase includes Bob / `premium-tier` with an `analyze` prompt and
expects `premium_complex`.

The local fixture is **Replay-shaped and profile-derived**, not a captured
production Replay record. It exists to exercise the adapter and audit contract
against a real public routing policy.

### 2. Synthetic stress fixtures

The gray-boundary, order, and grouping fixtures are explicitly synthetic. They
are analyzer/benchmark counterexamples, **not evidence that vSR currently has a
bug**.

A future live experiment can replace the synthetic fixture with actual
Router Replay captures while keeping the same audit/reporting layer.

## Native Replay compatibility

The adapter accepts the public Router Replay field names used by vSR, including:

```text
decision
selected_model
route_diagnostics
signals
projection_scores
signal_confidences
signal_values
tool_trace
session_policy
outcomes
```

Unknown fields are preserved in `raw_record`; missing optional fields remain
empty rather than being guessed.

## Interpretation discipline

- `PASS` for baseline reproduction means the **PoC evaluator**, using the
  profile-derived rule snapshot in the fixture, reproduces the Replay-shaped
  record's decision/model.
- `FAIL` for order/grouping means the two controlled synthetic paths produce
  different terminal route states.
- It does **not** automatically label the upstream Semantic Router as buggy.
- A real upstream defect claim requires the same residual to be reproduced
  against a live/current router path and captured in native Router Replay.

## Research mapping

```text
local perturbation invariance
→ counterfactual boundary robustness

permutation invariance
→ order / commutator residual

grouping invariance under lossy state reduction
→ associator residual
```

The intended research direction is to evolve these from fixtures into reusable
Router Replay evaluation primitives and, eventually, a benchmark.
